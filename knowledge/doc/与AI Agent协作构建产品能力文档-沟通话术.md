# 与 AI Agent 协作构建产品能力文档：沟通话术

## 1. 沟通目标

明天与另一个 Agent 沟通时，不要一开始就要求它直接批量写能力文档。更合适的方式是先提供完整背景，让 Agent 依次完成：

```text
模板评审 -> 分层规则确认 -> 原始资料清单 -> 一个试点初稿
```

这样可以先验证方法和模板，再扩大到更多能力，避免把模板问题和内容问题混在一起。

## 2. 开场背景说明

可以直接复制以下内容发送给 Agent：

```text
我正在构建公司平台产品的能力图，当前已经梳理了能力和能力特性，下一步要补充能力文档。

目前我们的暂定定义是：

- 能力：产品面向某类业务目标，能够提供的完整结果或解决方案。
- 特性：能力下具体可使用、可验证的功能点。
- 场景：能力发生和使用的业务情境。
- 支持项：设备型号、协议、版本、接口等支持范围或实现条件。

例如：

能力：呼叫器信号接入与业务联动

特性：
- 呼叫器信号触发任务下发
- 呼叫器信号改变库位状态
- 信号与库位、任务规则绑定

支持项：
- 支持康耐德型号 IO
- 支持研华型号 IO

我会提供一份能力文档模板，以及若干能力和特性资料。

请先不要直接写完整文档，按以下顺序协助我：

1. 审查能力文档模板是否过度设计。
2. 指出字段重复、缺失，以及哪些字段不适合让负责人填写。
3. 判断能力、特性、场景和支持项是否存在层级混用。
4. 给出精简后的模板建议。
5. 根据最终模板，列出生成能力文档所需的原始资料清单。
6. 建议选择哪些能力作为第一批试点。

要求：

- 不要根据常识猜测产品事实。
- 资料不足、存在冲突或无法确认的内容，统一标记为“待确认”。
- 重点考虑模板是否便于 AI 生成、负责人审核和后续维护。
- 请说明每项调整的原因。
```

## 3. 模板评审阶段

把当前模板发给 Agent 后，可以继续发送：

```text
请按刚才的评审标准，逐项检查这份模板。

请用以下格式输出：

| 原字段 | 问题 | 建议 | 原因 | 是否保留 |
```

重点关注以下问题：

- 字段是否过多，是否增加负责人负担。
- 字段之间是否存在重复。
- AI 是否能够从资料中提取该字段。
- 负责人是否能够快速确认该字段。
- 资料缺失时是否可以明确标记为“待确认”。
- 模板是否适用于不同类型的能力。

## 4. 原始资料清单阶段

模板调整完成后，发送：

```text
现在请基于调整后的模板，整理一份“能力文档原始资料准备清单”。

请区分：

- 必须提供的资料
- 有则更好的资料
- 由负责人确认的内容
- AI 不应自行推断的内容
```

建议让 Agent 同时说明每类资料的用途，以及资料缺失时应该如何标记。

## 5. 试点初稿阶段

选择一个能力进行试点后，发送：

```text
请根据以下资料生成能力文档第一版。

要求：

1. 严格按照最终模板输出。
2. 区分能力、特性、场景和支持项。
3. 不确定内容放入“待确认问题”。
4. 每个核心特性尽量说明触发条件、系统行为和业务结果。
5. 保留资料来源。
6. 文档末尾增加：
   - 资料覆盖情况
   - 资料缺口
   - 负责人重点审核事项
```

## 6. 负责人审核阶段

AI 初稿生成后，不要直接发布。把初稿交给能力负责人，要求重点确认：

- 能力定义是否准确。
- 特性是否完整、不重复且层级正确。
- 业务流程是否符合实际产品行为。
- 支持范围和限制条件是否准确。
- 异常行为是否遗漏。
- 待确认问题是否已经有明确结论。

可以记录以下数据，用来判断方法是否有效：

- AI 初稿生成耗时。
- 负责人审核耗时。
- 负责人修改比例。
- 最常缺失的资料类型。
- 最常见的层级错误。

## 7. 与 Agent 沟通时的基本原则

### 7.1 先审方法，再写内容

先让 Agent 检查模板和分层规则，确认方法可行后再生成文档。

### 7.2 事实和推测必须分开

产品事实必须来自原始资料或负责人确认。AI 可以整理、归纳和发现缺口，但不能自行补全未知信息。

### 7.3 优先试点，不要一开始批量生成

先选择三到五个能力，至少覆盖资料完整、资料分散和信息不足三种情况。

### 7.4 让 Agent 输出审核辅助信息

除了文档正文，还应要求输出资料覆盖情况、资料缺口、冲突信息和负责人重点审核事项。

### 7.5 保留来源和版本

每个重要结论应尽量对应原始资料来源，并记录文档负责人、审核时间和版本号。

## 8. 明天沟通的最小成功标准

明天不必完成全部能力文档。只要完成以下结果，就说明沟通有效：

- Agent 理解了能力、特性、场景和支持项的区别。
- 模板完成一轮过度设计检查。
- 得到一份原始资料准备清单。
- 确定三到五个试点能力及其负责人。
- 至少生成一篇可供负责人审核的能力文档初稿。
