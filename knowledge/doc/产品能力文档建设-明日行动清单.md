# 产品能力文档建设：明日行动清单

## 1. 明天的目标

明天不追求立刻完成大量能力文档，重点是完成三件事：

1. 验证能力模板是否过度设计。
2. 确定能力、特性、场景和支持项的分层方式。
3. 为后续 AI 生成初稿准备统一的原始资料清单和试点能力。

## 2. 到公司后的执行顺序

### 第一步：准备现有模板和样例

整理并带上：

- 当前能力文档模板。
- 已经完成的能力和特性清单。
- 一篇已有的能力文档或历史材料。
- 两到三个不同类型的能力样例。
- 能力负责人和相关产品、研发、实施人员名单。

目标产出：一份可以被评审的模板和样例，而不是停留在想法层面。

### 第二步：检查模板是否过度设计

逐项检查模板字段：

- 这个字段是否真的帮助理解、使用或维护能力？
- AI 是否能从原始资料中提取这个字段？
- 能力负责人是否能快速确认这个字段？
- 这个字段是否和其他字段重复？
- 资料缺失时，是否可以标记为待确认？

建议把字段分成三类：

- **必填字段**：能力定义、核心特性、边界、依赖、待确认问题。
- **按需填写字段**：流程图、典型案例、配置说明、异常处理。
- **系统维护字段**：负责人、版本、状态、更新时间、资料来源。

如果一个字段既无法帮助负责人审核，也无法帮助使用者理解，应考虑删除或合并。

### 第三步：统一能力分层规则

用以下规则检查现有清单：

| 判断对象 | 应该回答的问题 |
| --- | --- |
| 场景 | 在什么情况下使用？ |
| 能力 | 产品能解决什么问题、提供什么结果？ |
| 特性 | 产品具体能做什么？ |
| 支持项 | 支持哪些设备、协议、版本或条件？ |

重点检查是否存在以下混用：

- 把客户场景直接当成产品能力。
- 把一个具体功能点提升为能力。
- 把设备型号、协议或版本和业务特性并列。
- 把实现方式写进本应稳定的能力名称。

以呼叫器为例，可以先统一为：

```text
能力：呼叫器信号接入与业务联动
特性：触发任务下发、改变库位状态、信号规则绑定
支持项：康耐德 IO、研华 IO、具体协议和版本
```

### 第四步：选择三到五个试点能力

建议选择以下组合：

- 资料完整、容易快速生成初稿的能力。
- 资料分散、需要整合多个来源的能力。
- 当前团队并不熟悉、可以验证“待确认问题”机制的能力。

为每个试点指定一名能力负责人，并记录负责人审核初稿所需的时间。

### 第五步：收集每个试点的原始资料

向能力负责人或相关团队收集：

- 能力背景、业务目标和典型使用场景。
- 已实现的特性清单。
- 业务流程、操作流程和页面截图。
- 配置方式、前置条件和权限要求。
- 设备、协议、接口、版本和系统依赖。
- 已知限制、异常行为和不支持范围。
- 已落地项目、客户案例和实施记录。
- 需求文档、方案、会议纪要、接口说明和历史文档。
- 尚未确认的争议点和待补充信息。

资料不完整时，先记录“缺什么”，不要让负责人为了补齐资料而重新写整篇文档。

### 第六步：用一个试点生成 AI 初稿

给 AI 的输入至少应包括：

- 最终模板。
- 能力名称和现有特性。
- 原始资料及来源。
- 明确的“不猜测、不擅自补全”要求。

要求 AI 输出：

1. 能力文档初稿。
2. 能力、特性、场景和支持项的分类结果。
3. 资料缺口和待确认问题。
4. 负责人需要重点审核的章节。

### 第七步：安排负责人审核并记录结果

让负责人重点回答：

- 定义是否准确？
- 特性是否完整且不重复？
- 哪些内容是错误的？
- 哪些内容只是部分支持？
- 哪些限制、依赖或异常行为没有写出来？
- 哪些待确认问题已经有结论？

记录以下指标：

- AI 初稿生成耗时。
- 负责人审核耗时。
- 负责人修改比例。
- 最常缺失的资料类型。
- 最常发生的层级错误。

## 3. 明天结束时应形成的结果

理想情况下，明天结束时应得到：

- 一份经过初步精简的能力文档模板。
- 一套能力、特性、场景、支持项的分层规则。
- 三到五个试点能力及其负责人。
- 每个试点的原始资料清单和缺口清单。
- 至少一篇 AI 生成的能力文档初稿。
- 负责人审核时间和修改意见的记录方式。

## 4. 明天先不要做的事情

- 不要先追求模板覆盖所有特殊情况。
- 不要在资料不足时让 AI 猜测产品行为。
- 不要一次性要求所有负责人完成全部文档。
- 不要把设备型号、协议和业务特性强行放在同一层级。
- 不要在试点前就确定复杂的文档管理流程。

## 5. 后续推进节奏

```text
模板评审
-> 选择试点
-> 收集资料
-> AI 生成初稿
-> 能力负责人审核
-> 复盘模板和资料清单
-> 扩大到更多能力
```

第一轮的成功标准不是文档数量，而是确认：负责人审核 AI 初稿是否明显比从零写作更快，并且文档准确性能够通过审核得到保障。
