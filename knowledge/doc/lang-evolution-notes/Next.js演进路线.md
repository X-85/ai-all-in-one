# Next.js 演进路线

一句话版：**React 只解决了"怎么画界面"，画界面的代码在哪跑、路由怎么定、首屏 HTML 从哪来，每个项目都得自己造一遍；Next.js 把这些决定收进框架，先给一张按页点菜的渲染策略菜单，最后干脆把服务器请回了组件内部。**

> 类型：框架 | 生态：React 全栈（npm） | 诞生：2016

姊妹篇：[JS-Node-TS演进路线](JS-Node-TS演进路线.md)、[Python演进路线](Python演进路线.md)、[Java演进路线](Java演进路线.md)、[Go演进路线](Go演进路线.md)、[Rust演进路线](Rust演进路线.md)。本文站在 JS 篇的顶端——Next.js 正是 JS→Node→React 那条链结出的框架；第四节的内核换代则呼应 Rust 篇。

## 一、React 留下的空位（2013-2016）

2013 年 Facebook 开源 React：界面拆成组件，数据变了框架自动算出最小 DOM 更新。这套"组件 + 声明式"的写法迅速统治了前端。但 React 管的只有"画"——真要上线一个网站，三件事它不管：

1. **首屏与 SEO**：通行做法是 SPA（单页应用）——服务器只回一个空 `<div>`，浏览器下载全部 JS 后在客户端现画界面。慢网络下用户盯白屏；搜索引擎爬虫抓到的是空壳，内容要等 JS 跑完才存在。
2. **工程配置**：webpack、Babel、热更新、代码分包，每个新项目人肉搭一遍，配置出了名地难维护。
3. **路由**：React 本身没有路由，各项目用 React Router 等方案自行拼装，服务端渲染更是少有人碰的硬骨头。

于是每个 React 项目都在重造同一副骨架。2016 年 10 月，Guillermo Rauch 的公司 ZEIT（2020 年更名 Vercel）发布 Next.js，思路一句话：**不做更好的 React，做替你做好决定的那一层**——

| React 不管的 | Next.js 替你定的 |
|------|------|
| 路由 | 文件即路由：`pages/about.js` 自动就是 `/about` |
| 首屏 | 每页默认服务端渲染（SSR）：Node 在服务器先把 HTML 画好再发 |
| 工程配置 | 零配置开箱：webpack/Babel/热更新/按页分包全部内置 |

注意这里的分界：React 是**库**（你调用它，结构你定），Next.js 是**框架**（它调用你，规矩它定）。这一步还呼应 JS 篇的因果链：SSR 要在服务器上跑 React，用的正是 Node 的 `http`——**JS 当年逃出浏览器，如今又借 Node 把"画界面"搬回服务器：发出去的是成品 HTML，浏览器只负责接管交互。**

## 二、渲染策略菜单化（2019-2020）

早期 Next.js 每次请求都让服务器现画一遍页面（纯 SSR）。但网站里大量页面根本不变——文档、博客、落地页，每次现画是白费服务器；而它们恰是 SEO 最看重的页。另一头，Gatsby 这类静态站生成器（构建时把全站画成 HTML 文件）走红，证明"预先画好"有市场，可全站静态又伺候不了个性化内容。

Next.js 的回答是把"在哪画 HTML"变成**每页一选的菜单**：

- **SSR**（`getServerSideProps`）：请求时现画。购物车、搜索结果页。
- **SSG**（`getStaticProps`）：构建时画好，请求只发文件。文档、博客。
- **ISR**（2020）：构建时画好 + 按秒级过期定时重画。静态的速度加上接近动态的新鲜度，第三条路。

同一个站点三种混用，哪个页面用哪种，就写在那个页面的文件里。框架的卖点从"帮你 SSR"进化成"**渲染地点按页可选**"。同期 9.0（2019）还送了两件礼物：动态路由（`pages/post/[id].js`）和 API Routes——在 `pages/api/` 下写个函数就能起后端接口，本质是 JS 篇里 `http.createServer` 的框架化封装。前端工程从此顺手就是全栈工程。

## 三、App Router 大改（2022-2023）

pages 这套用久了，死角显现：

1. 取数只能写在页面级（`getXxxProps`），页面深处组件要的数据得一层层 props 传下去，多个请求还只能排队（数据瀑布流）；
2. 给服务器用的取数代码也跟着打进浏览器 bundle，越堆越重；
3. 布局切换时整页重新渲染，导航栏闪一下这类细节忍了很多年。

同一时间，React 团队 2020 年底公开了酝酿已久的 **React Server Components（RSC）**：组件可以直接在服务器上执行，只把需要交互的部分发往浏览器。Next.js 是第一个把它完整落地的框架——

- 2022 年 10 月，Next 13 引入 `app/` 目录（beta）；2023 年 5 月，13.4 转正，史称 **App Router**。
- 文件约定升级：`app/page.tsx` 是页面，`app/layout.tsx` 是包住子路由的布局（导航不再闪）。
- **默认值反转**：所有组件默认是 Server Component——留在服务器跑，产物是 HTML，不进浏览器；要用 useState、onClick，在文件顶加一行 `"use client"`，它才进浏览器。
- 取数不再有专门 API：服务器组件里直接 `await` 数据库或接口，像写普通异步函数一样。
- 2023 年 10 月，Next 14 里 Server Actions 转正：表单提交直接调用跑在服务器上的函数，不必手写接口。

这是 Next.js 史上最痛的一次改版，痛在它动的是地基：**pages 时代默认一切在浏览器，app 时代默认一切在服务器**。代码的默认执行位置反了，取数、缓存、路由、布局的写法全是这个决定的下游，只能集体换血。

## 四、还债与换内核（2021-2026）

两件事同时在进行。

**1. 构建内核换成 Rust。** 2021 年 Next 12 用 Rust 写的 SWC 替换 Babel 做代码转译；2022 年起又以 Rust 打包器 Turbopack 接替 webpack：2024 年 Next 15 开发模式稳定，2025 年 Next 16 转正为默认，webpack 退居可选。用户视角命令一个没变——正是速查表的规律"**工具链可以换内核，外壳不变**"；内核为什么用 Rust 写，见 Rust 篇。

**2. 缓存哲学回调。** App Router 初版（13/14）替用户做了个激进决定：默认缓存一切——fetch 结果缓存，能静态化的页面全静态。初衷是性能，反噬是"数据改了页面不更新"、排查极难。Next 15（2024 年 10 月）公开回调：默认不缓存，要缓存显式声明（15.5 起的 `"use cache"` 指令、16 的 Cache Components 实验特性）。这场反复值得记一笔：框架靠"替你做决定"立国，决定做错了，也得由框架公开还债。

## 五、三个必要词汇

- **库 vs 框架**：库是你调用它（React：路由、构建、渲染方式全由你定）；框架是它调用你（Next.js：文件放哪、数据怎么取、代码跑在哪，它定）。佐证：react.dev 2023 年改版后，官方"新建 React 项目"教程第一推荐就是 Next.js——库的配置层被框架收编，是这十年前端的总走向。
- **渲染策略（SSR/SSG/ISR/CSR）**：回答一个问题——HTML 在哪一刻、由谁画。浏览器里现画（CSR，SPA 老路）、构建时画好（SSG）、请求时现画（SSR）、画好但定时过期（ISR）。Next.js 的卖点从来不是其中某一种，而是**按页混用**。
- **Server / Client 组件**：App Router 的国界线。默认服务器组件（留在 Node，产出 HTML，不进浏览器 bundle）；`"use client"` 之后是客户端组件（进浏览器，有 useState/onClick）。一行注释决定代码跑在哪个世界——呼应 JS 篇那句话：**语言没变，换的是周围的世界。**

## 六、工程化：一个 Next.js 项目怎么构建和运行

演进讲完，补实务：用 Next.js 从零到跑起来，标准动作是——

```text
npx create-next-app@latest → 脚手架生成项目(问 TypeScript/Tailwind/src 目录,一路回车也能跑)
npm run dev     → 开发服务器 localhost:3000,改代码热更新
npm run build   → 产出 .next/ 生产构建(必经)
npm run start   → 用生产构建起 Node 常驻服务器
npm test        → 脚手架默认不配测试,需自行加 vitest 等
```

三个关键认知：

1. **文件树即 URL 树**。`app/page.tsx` 是首页，`app/blog/[slug]/page.tsx` 是动态路由，`layout.tsx` 包住子路由。没有路由配置文件，约定就是配置。旧 `pages/` 目录是上一代约定，新项目一律 `app/`。
2. **构建必经，且产物要 Node 伺候**。`.next/` 不是一堆静态文件：带 SSR/Server Actions 的站，`next start` 起的是常驻 Node 进程（JS 篇 Q7 的模式）。纯内容站可用 `output: 'export'` 退回纯静态，扔给任何静态服务器都行——第二节的渲染策略菜单，在部署形态上再次生效。
3. **默认是服务器组件**。AI 生成 App Router 代码时，没加 `"use client"` 的组件全在服务器跑；按钮点了没反应、报 useState 不存在，第一反应查这一行。取数直接 `await` 写在组件里，不是 `useEffect + fetch` 的老套路。

AI 验收三连：`npm run dev` 起来打开 3000 端口；改 `app/page.tsx` 一行看热更新；`npm run build && npm run start` 过生产构建。测试默认不自带，要验收测试先让 AI 配好框架（vitest）。

## 七、因果链小结

```text
React 只管画界面,SPA 白屏/SEO 空壳/配置地狱   → 有了 Next.js(2016,框架接管路由+SSR)
不是每页都值得每次现画                    → 渲染策略菜单化(2019-2020,SSG/SSR/ISR 按页混用)
页面级取数束缚组件,浏览器 bundle 越来越重    → App Router + 服务器组件(2022-2023,服务器回到组件内部)
Babel/webpack 撞性能墙,激进缓存反噬        → Rust 内核换代 + 缓存默认回调(2021-2026)
```

## FAQ

约定：这里的问答随实际疑问追加，每条回答控制在几句话内；问题来自真实使用中的困惑，不预设。

**Q1：Next.js 会取代 React 吗？**
方向反了：Next.js 离不开 React，它是"用 React 造网站"的那一层。真实的走向是 React 官方教程 2023 年起把 Next.js 列为第一推荐——不是谁取代谁，是库的配置层被框架收编。

**Q2：学 Next.js 之前要先会 React 吗？**
要，而且分两段：组件、props、state、hooks 这些 React 基础全用得上；但 App Router 里"组件默认跑在服务器"是 React 入门教程没讲的新世界，要按本文第三、五节重新对齐认知。

**Q3：写了 "use client"，整页就变回老 SPA 了吗？**
不是。它标的是一个边界：该文件及其引用的组件进浏览器，其余部分仍留在服务器。典型页面两端各占一半——服务器出内容，客户端小组件管交互。

**Q4：为什么从 pages 换到 app 这么痛？**
因为换的不是 API 是地基：代码默认执行的位置从浏览器反转为服务器。取数、缓存、路由、布局的写法全是这个决定的下游，所以只能集体换血。

**Q5：必须部署在 Vercel 吗？**
不必。`next build && next start` 就是一个 Node 进程，自建服务器、Docker、任何云都能跑。Vercel 的差异是零配置、新特性最先可用——开源框架与商业平台共生，这也是 Next.js 争议最大的地方。

**Q6：Turbopack、SWC 和 webpack 是什么关系？**
Next.js 构建内核的两代换血：SWC（Rust 写）换掉 Babel 做转译，Turbopack（Rust 写）换掉 webpack 做打包，Next 16 起默认。命令和配置入口没变——"外壳不变，换内核"。

**Q7：Next.js 算语言吗？**
不算。语言要有自己的语法和编译器，Next.js 两者都没有：写的仍是 JS/TS（加 React 的 JSX 扩展），报错的是 SWC，解析的是 TS。它是用 JS/TS 写的框架——文件约定 + 运行时 + 工具，地位相当于 Spring 之于 Java、Django 之于 Python。它像语言是因为行话密、文件名带魔法，但约定不是语法：文件名写错只是不生效，语法写错才编译不过。把 JS 篇的三层词汇加一层就是完整地图——Next.js 在框架层，底下是 JS/TS 语言层和 Node/浏览器运行时层。
