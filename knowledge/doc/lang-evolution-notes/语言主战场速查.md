# 语言主战场速查

这是一张**查表，不是教程**：只回答"X 主要用来干什么、什么时候不该选 X"。它为什么长成这样，见各篇演进路线（表内互链）；怎么构建怎么跑，见[构建工具链速查](构建工具链速查.md)。

## 三、中间件与平台

| 主体 | 主要方向 | 代表场景 | 不适合什么 |
|------|---------|---------|-----------|
| [Redis](Redis演进路线.md) | 缓存、会话、排行榜/计数、简单队列 | 系统的第一块加速板 | 大 Value 冷数据、复杂查询与强一致（内存 KV，不是主库） |

| [MySQL](MySQL演进路线.md) | OLTP 事务主库、Web 应用数据底座 | 绝大多数业务的第一个数据库 | 分析型大扫描（OLAP）、schema 频变的文档型场景 |
| [Docker](Docker-K8s演进路线.md) | 交付标准化：环境打成镜像 | CI/CD、本地与线上环境一致 | 单文件脚本的小工具（没必要） |
| [K8s](Docker-K8s演进路线.md) | 编排：弹性伸缩、自愈、声明式部署 | 多服务云上底座 | 单机小项目、强内核/图形耦合负载（太重） |

## 四、行间规律（选型心法）

1. **第一问不是"哪门语言最好"，是"哪个生态里我要的轮子最全"**——主战场就是轮子最全的地方。选 Python 选的是生态（Python 篇），这一条对表里每一行成立。
2. **两门都说"能做"的地方，看帝国在哪一层**。Java 与 Go 同处云时代：Java 的帝国在应用层（Spring + 大数据），Go 的帝国在基础设施层（容器 + 网络）——分界线是**你写的是业务还是底座**。
3. **"不适合"列比"主要方向"更防错**。选型事故多半是拿 A 的短板去碰 B 的长板（拿 Python 扛高并发纯计算、拿 Redis 当主数据库）。先排掉不适合，剩下的都不太会错。
