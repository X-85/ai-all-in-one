# Vue 演进路线

一句话版：**Angular 的数据绑定好用，但全家桶太重——Vue 把这部分单独抽成轻量库，让你从一行 `<script>` 标签开始、按需长成全家桶。这份"渐进"让它收下海量项目，也让 2→3 换代拖了五年；而换代路上顺手造的 Vite，最终成了整个 JS 生态的构建标准。**

> 类型：框架 | 生态：前端渐进式框架 + Vite 构建标准 | 诞生：2014

姊妹篇：[JS-Node-TS演进路线](JS-Node-TS演进路线.md)、[Python演进路线](Python演进路线.md)、[Java演进路线](Java演进路线.md)、[Go演进路线](Go演进路线.md)、[Rust演进路线](Rust演进路线.md)、[Next.js演进路线](Next.js演进路线.md)。本文与 Next.js 篇同源不同路：React 生态把工程决定收进 Next.js 这层框架，Vue 生态把决定收进 Vue 自家与 Nuxt——两篇对照着读最清楚；第三节的换代之痛呼应 Python 篇的兼容哲学表，第四节的 Vite 换内核呼应 Rust 篇。

## 一、jQuery 与 Angular 之间的空位（2013-2014）

2013 年做交互界面，主流是两个极端：

| | jQuery | Angular 1.x（2010） |
|------|------|------|
| 写法 | 命令式：`$('#tip').show()` 手动改 DOM | 声明式：`ng-model` 等指令 + 双向绑定 |
| 代价 | 状态散落在 DOM 里，交互一多就乱 | 全家桶一次全信：模块、依赖注入、指令一套仪式 |

尤雨溪（Evan You）当时在 Google Creative Lab，工作是把大量实验性界面快速做出来跑在浏览器里。他最喜欢 Angular 的数据绑定，受不了它其余的部分，于是把绑定抽出来做一个只管视图层的库：2013 年动工，2014 年 2 月首次公开发布，取名 Vue——法语"视图"，发音与 view 同音。

卖点是两条，也定义了 Vue 的身份：

1. **模板是合法 HTML**：`<div>{{ msg }}</div>` 再加 `v-if`、`@click` 几个指令就活了，设计师也读得懂，可以直接塞进既有页面。对照 React 的选择：JSX，一切皆 JS（JS 篇第五节的哲学分野，开局就摆在这里）。
2. **渐进式（progressive）**：核心库只负责"数据变了、视图自动更新"；要路由加 vue-router，要全局状态加 Vuex，要工程化上单文件组件和构建工具——**每一层都可选，不强求一次全信**。这是"渐进式框架"的本义，也是它对 Angular 式全家桶的直接回答。

2014 年 10 月，项目经 Hacker News 与 Laravel 社区（框架作者公开推荐）走红，尤雨溪自此全职维护。从此"三大框架"的第三极有了雏形。

## 二、模板路线成型：Vue 2 与虚拟 DOM（2015-2018）

Vue 1 的绑定是细粒度直连：每个数据与每个 DOM 节点记着对应关系，一变就精确改。小页面极快，页面一大内存里的绑定记录爆炸，而且渲染写死在 DOM API 上——服务端渲染（SSR）无门。

React 已证明另一条路：虚拟 DOM。Vue 2.0（2016-10）重写渲染层引入虚拟 DOM（受 snabbdom 启发），大页面性能过关，SSR 大门打开——Node 里跑组件输出 HTML，与 Next.js 篇第一节是同一个逻辑。同年 Nuxt 诞生，与 Next.js 之于 React 完全对称。

同期，Vue 的招牌生态成型：

- **单文件组件（SFC）**：`.vue` 文件里 `<template>`/`<script>`/`<style>` 三段，一个组件一个文件。今天看稀松平常，当年是相对 React（JSX 与样式方案各自为战）的明确卖点。
- **官方周边一条龙**：vue-router、Vuex、vue-cli、devtools 全部官方出品、版本互相对应，省掉选型。全家桶齐了，但仍是可选件——渐进式不动。
- 2016 年起中文生态爆发：饿了么开源 Element，中后台场景 Vue 几成默认；中文文档与社区同期一流。2016 年中，GitHub star 数超过 React（下载量仍次于），三大框架格局就此定型：React（JSX、大厂背书）、Angular（企业全家桶）、Vue（渐进式、模板）。

Vue 2 的响应式用 `Object.defineProperty` 逐属性拦截——能用，但出生即带暗坑：给对象**新增**属性、按**下标**改数组，拦截不到，得用 `this.$set()` 打补丁。这个无解的局限，埋下第三节的伏笔。

## 三、Vue 3：Proxy 重写与组合式 API（2018-2022）

Vue 2 如日中天时，三个死结逼近：

1. **类型推不动**：Options API 一切经 `this` 访问，TS 对 `this.xxx` 的推导残缺；框架本体还是 Flow 写的——TS 已是大型前端标配的年代（JS 篇第三节），这是硬伤。
2. **响应式到顶**：defineProperty 的暗坑无法在底层修复，换实现只能换大版本。
3. **逻辑复用乱**：mixins 命名冲突、来源不明；Options API 按选项分块（data 一块、methods 一块），同一功能的代码散落各处，组件一大就失控。

Vue 3 的回答是一次彻底重写：

- **Proxy 响应式**（ES2015）：拦截对象的一切读写——新增属性、数组下标全透明；依赖追踪改为惰性，初始化不再全量递归。
- **组合式 API（Composition API）**：代码从"按选项分块"改为"按功能组织"——一个功能的数据、计算、监听写在一起，再抽成 composable 函数跨组件复用（思想对标 React Hooks）。这条路不平静：2018 年底第一版提案在社区引发强烈反弹，官方收回重做，2019 年以 `setup()` 的形式定型——框架听用户的，这是 Vue 史上最重要的一次设计回调。
- **框架本体改用 TypeScript 重写**，类型成为一等公民，另带性能补课（静态标记、按需更新）。

2020-09-18，Vue 3.0 发布。但对用户而言，发布才是长痛的开始：

- Vue 3 落地 ≠ Vue 2 退场。官方给出 `@vue/compat` 兼容模式与迁移指南，Vue 2 的生命末期两次延后，最终定格 2023-12-31；甚至把组合式 API 反向移植进 Vue 2.7（2022-07），让老项目先学新写法再搬家。
- 2022-02-07，npm 默认版本才切到 Vue 3——距 3.0 发布 17 个月，距重写立项已四年。

放进兼容哲学表看最清楚：Python3 敢断痛十二年；Java 从不断、用兼容统治；ES6 只加不断；**Vue 选了中间路线——新旧并轨双轨五年，拿时间换平滑**。渐进式当年怎么把存量项目收进来，换代时就怎么被存量拖住：Next.js 篇说"替你做决定的是框架，替你还债的也是它"，Vue 版的这句话是——**拉新用的哲学，就是还债用的哲学**。

## 四、还债与反哺：Vite 与编译器的回归（2020-2026）

**1. Vite：顺手造的工具成了全生态标准。** Vue 项目在 vue-cli（webpack）下越长越大，开发服务器冷启动动辄几十秒——先全量打包完，才能看见第一屏。尤雨溪的解法不是"把打包做快"，而是取消打包：2017 年起主流浏览器已原生支持 ES Module，**开发时浏览器请求哪个文件，服务器就现编译哪个**——按需、秒级启动；生产构建仍交给 Rollup 求稳。这就是 Vite（2020 年亮相，法语"快"），2021 年 Vite 2.0 转为框架无关，此后 React、Svelte、Solid、Nuxt、Astro 全部把它当底座或兼容其插件体系——一个 Vue 的工具，长成了整个 JS 生态的构建标准。速查表规律"工具链可以换内核，外壳不变"在 Vite 身上再多一层：**换的不止内核，是范式——从"先打包再运行"到"开发不打包"**。而它自己也在换内核：Rust 写的 Rolldown 正在接替 Rollup 生态位——Rust 篇"新一代工具链内核"的帝国再添一城。

**2. TS 长跑补课。** Vue 3.0 只是类型合格的起点：3.3（2023）让 `defineProps` 直接吃外部类型，3.4（2023-12）底层重写响应式系统再提速，3.5（2024-09）响应式 props 解构转正——从"能用 TS"到"写得舒服"，又补了四年课。

**3. Vapor Mode：虚拟 DOM 不是终点。** 2023 年公布的方向：编译器直接生成精确的 DOM 操作代码，运行时跳过虚拟 DOM 与 diff。回头看是一条绕圈的回归路——Vue 1 细粒度直连、Vue 2 虚拟 DOM、Vue 3 静态标记、Vapor 全编译——声明式 UI 的重心，正从"运行时更聪明"移向"编译器更懂你"。

## 五、三个必要词汇

- **渐进式框架**：核心只管视图层，路由、状态、构建、SSR 全是可选叠加层，"不强求一次全信"是 Vue 的国策。从一个 `<script>` 增强旧页面，到全家桶起新项目，都在同一体系内——反面参照是 Angular 的一次全信；代价见第三节：存量越重，换代越慢。
- **响应式（reactivity）**：Vue 的心脏，原理一句话——**拦截数据的读写：读的时候记下"谁在用我"，写的时候通知这些人**。Vue 2 用 defineProperty（逐属性、有暗坑），Vue 3 用 Proxy（全透明）。与 React 的根本分野也在这里：React 靠不可变数据加 `setState` 显式声明"我变了"，Vue 靠代理自动追踪"谁变了"。写代码的直接后果就是 ref 的 `.value`、解构丢响应式这些规则。
- **选项式 / 组合式 API**：同一框架的两种代码组织法。选项式（data/methods/computed 分块）是 Vue 2 时代的默认，好入门；组合式（`<script setup>` 里按功能组织 ref/computed/watch）是 Vue 3 的正统，逻辑可抽成 composable 复用。新代码一律组合式，读老项目仍需认识选项式——Vue 2.7 的反向移植说明：官方也认为两者会长期共存。

## 六、工程化：一个 Vue 项目怎么构建和运行

演进讲完，补实务：用 Vue（Vite 方案）从零到跑起来，标准动作是——

```text
npm create vue@latest → 官方脚手架(问 TS/Router/Pinia/测试,一路回车得最小项目)
npm run dev       → Vite 开发服务器 localhost:5173,按需编译秒启动,热更新
npm run build     → 产出 dist/ 纯静态文件(必经)
npm run preview   → 本地起静态服务器预览生产构建
npm run test:unit → 脚手架创建时勾选 vitest 才有,默认不配
```

三个关键认知：

1. **`.vue` 单文件组件是基本单元，`<script setup>` 是标准写法**。AI 生成 Vue 代码若给出 Options API 或裸 `<script>`，先要求改成 `<script setup>` 加组合式 API，再谈别的。
2. **SPA 产物是纯静态**。`dist/` 扔给任何静态服务器、CDN、对象存储都能跑——与 Next.js（`.next/` 要 Node 常驻伺候）是部署形态的两极。要 SSR、文件路由、全栈，升 Nuxt：Vue 版的 Next.js，渲染策略菜单那套照样适用。
3. **响应式有边界，bug 多半出在边界上**。`ref` 在脚本里要 `.value`；`reactive` 对象被解构或整体替换会断开代理；props 直接解构要 3.5 才不丢响应式。"改了数据页面没变"，先查这三条。

AI 验收三连：`npm run dev` 起来打开 5173 端口；改 `App.vue` 一行看热更新；`npm run build && npm run preview` 过生产构建。测试默认不带，要验收测试先在脚手架勾 vitest。

## 七、因果链小结

```text
jQuery 手动改 DOM 太散,Angular 全家桶太重        → Vue 诞生(2014,渐进式:数据绑定单卖,从一行 script 起步)
细粒度绑定撑不住大页面,SSR 无门                  → Vue 2 引入虚拟 DOM(2016),模板路线与官方全家桶成型
this 推不动类型,defineProperty 到顶,mixins 乱    → Vue 3 重写(2018-2022,Proxy 响应式 + 组合式 API),并轨五年还兼容债
webpack 冷启动慢成共识,浏览器已原生 ESM           → Vite(2020,开发不打包),从 Vue 工具反哺为全生态构建标准
```

## FAQ

约定：这里的问答随实际疑问追加，每条回答控制在几句话内；问题来自真实使用中的困惑，不预设。

**Q1：Vue 和 React 到底怎么选？**
表层是模板 vs JSX，里层是"数据怎么变"：Vue 响应式自动追踪，React 不可变数据加显式 setState。工程能力今天相当（全栈有 Nuxt 对 Next.js，构建同吃 Vite 生态），实际决策常落在团队存量与就业市场（React 岗更多）。技术差异没有传言那么大。

**Q2：现在入门，Vue 2 的资料还能用吗？**
概念（模板、指令、组件）基本通用，写法（Options API、`$set`）已过时。只学 Vue 3 组合式；Vue 2 已于 2023 年底停止维护，新项目没有理由从 2 开始。

**Q3：ref 和 reactive 用哪个？**
默认 ref：什么类型都能装，代价是脚本里要 `.value`。reactive 只收对象，解构、整体赋值都会丢响应式。官方风格也已倾向 ref 为主。

**Q4：Vite 是 Vue 专属的吗？**
同一个作者，但 Vite 是框架无关的独立项目，2021 年起就是 React、Svelte、Nuxt、Astro 等的共同底座。用 React 不碰 Vue 完全正常——大概率你已经在用 Vite。

**Q5：为什么 Vue 2 到 3 拖了那么多年？**
重写动了地基（响应式实现、API 组织），而渐进式收进来的存量项目太多，生态库要逐个跟进。官方选择双版本并轨加反向移植（2.7）平滑过渡——渐进哲学在换代期的再一次应用，代价是双轨五年。

**Q6：Vue 算语言吗？**
不算。写的是 JS/TS 加模板语法；模板由框架自带的编译器翻译成渲染函数。文件名或指令写错只是不渲染，语法写错才编译不过——约定不是语法。它站在 JS 篇三层模型的框架层，底下是 JS/TS 语言层与浏览器/Node 运行时层。

**Q7：Vapor Mode 会淘汰虚拟 DOM 吗？**
方向是编译器直接生成精确 DOM 操作、跳过虚拟 DOM diff。对 Vue 内部是大的实现变化，对使用者 API 基本不变——又是"外壳不变，换内核"。新项目不必等它落地。
