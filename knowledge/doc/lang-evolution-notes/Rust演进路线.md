# Rust 演进路线

一句话版：**C/C++ 快但内存漏洞太多，GC 语言安全但进不了内核，所以 Rust 把安全保障搬进了编译期；语言稳定后配上 Cargo，工业化才起飞。** 这是一条因果链：每一步都在解决上一步留下的死角。

姊妹篇：[JS-Node-TS演进路线](JS-Node-TS演进路线.md)。两条路线惊人地共用一个手法——**把错误从运行时左移到开发期**：TS 左移的是类型错误，Rust 左移的是内存错误。

配套速查（rustc/cargo 等工具命令）：[构建工具链速查](构建工具链速查.md)

## 一、动机（2006-2010）：系统编程的"既要又要"难题

系统编程——操作系统、浏览器、数据库——长期被 C/C++ 统治，代价是内存安全：这块内存已经释放了还在用（use-after-free）、往数组界外写了数据（缓冲区溢出）。微软和 Chrome 团队都统计过：**约 70% 的严重安全漏洞属于内存错误**，而且是几十年修不完的顽疾，因为它靠的是程序员自觉。

另一条路是带 GC（垃圾回收）的 Java/Go：运行时自动兜底，安全。但 GC 有停顿和运行时开销，进不了内核、嵌入式这些要贴着硬件跑的场景。

于是问题变成：**能不能既要 C 的性能，又要 GC 的安全？** Rust 最初是 Mozilla 员工 Graydon Hoare 2006 年的私人项目（名字来自锈真菌，取其顽强适应的意象），2009 年获 Mozilla 赞助，就是冲着这个"既要又要"去的。

## 二、核心创新（2010-2015）：所有权系统

内存安全此前只有两种保障方式，Rust 开出了第三条路：

| 路线 | 谁负责安全 | 代价 |
|------|-----------|------|
| C/C++ | 程序员手动管理 | 漏洞占严重安全漏洞约七成 |
| Java/Go | 运行时 GC 兜底 | 停顿和开销，进不了内核 |
| **Rust** | **编译期证明** | 学习曲线陡，编译慢 |

具体机制：**每个值有唯一所有者**，赋值和传参默认是"移动"（原变量失效）；可以临时"借用"，但必须通过**借用检查器**（borrow checker）的验证——借用的存活期不能超过所有者，不能一边读一边写。不合规直接编译失败。内存的释放不需要程序员写（C 的做法）也不需要 GC 扫（Java 的做法），而是编译器在编译期算好位置、插入释放代码——运行时零开销。

代价出了名：新手的代码在别的语言合法，在 Rust 就是编译不过，"和借用检查器搏斗"是全体 Rust 学习者的共同记忆。本质是编译器逼你在写代码时就想清楚"谁拥有这个值、谁能改它"——把原本生产环境才炸的事故，提前到了敲键盘的瞬间。

值得一提的魄力：1.0 之前 Rust 曾内置 GC、语法也大改过，后来彻底推倒重来、移除 GC。这种自我革命在语言史上少见。

2015 年 5 月，Rust 1.0 发布，承诺向后兼容。

## 三、工业化（2014-今）：Cargo 与采纳曲线

安全只是内功，语言稳定之前没人敢用（谁敢把业务押在一个语法每年都变的东西上？），1.0 的稳定承诺解除了这层顾虑。

外功是 Cargo：Rust 自带的包管理器 + 构建工具二合一（`Cargo.toml` 声明依赖，crates.io 是官方仓库），把 C/C++ 几十年碎片化的 make/cmake 时代终结掉，给到了 npm 级的上手体验。**内功加外功，采纳曲线才开始陡增**：

- 2017 年 Firefox 组件用 Rust 重写（项目起源于 Mozilla 的 Servo 实验浏览器）；
- AWS 的微虚拟机 Firecracker、Discord 的核心服务（从 Go 迁回 Rust）；
- Android、Windows 内核组件相继引入 Rust；2022 年 Linux 内核正式接受 Rust 代码——史上第二种被内核接纳的语言；
- 新一代 JS 工具链集体换 Rust 内核：SWC、Biome、tsgo（微软用 Rust 重写的 TS 编译器）、Codex CLI；
- Stack Overflow"最受喜爱语言"从 2016 年起连续多年第一。

背后还有一股顺风：2022 年起美国国家安全局（NSA）、网络安全机构 CISA 相继发文推荐内存安全语言——内存安全从工程话题升格成了政策话题，Rust 是唯一"无 GC 的内存安全"选项。

## 四、三个必要词汇

- **所有权（ownership）**：内存管理的第三条路——不靠程序员自觉，不靠运行时兜底，靠编译期证明。Rust 一切的根基。
- **借用检查器（borrow checker）**：把内存错误从生产环境左移到编译期的那个执法者。Rust 难学的来源，也是 Rust 安全的来源——同一枚硬币的两面。
- **Edition（版本 editions）**：Rust 的兼容性机制。2015/2018/2021/2024 各是一个 edition，新 edition 可以改语法但新旧代码能互操作。在项目的 `Cargo.toml` 里会看到 `edition = "2021"`，读 Rust 项目时别把它当成"语言版本号"。

## 五、工程化：一个 Rust 项目怎么构建和运行

安装 Rust 实际装的是 rustup（工具链管理器，角色类似 nvm），它带出两样东西：`rustc`（编译器，语言本体的执行入口）和 `cargo`（项目管家）。从零到跑起来：

```text
cargo new hello       → 生成项目骨架:Cargo.toml(项目清单) + src/main.rs
cargo add serde       → 加依赖,写入 Cargo.toml,构建时自动从 crates.io 下载
写代码                → src/ 下的 .rs 文件
cargo run             → 编译并运行(开发时最常用)
cargo build --release → 出优化版编译产物
cargo test            → 跑测试
```

三个关键认知：

1. **`Cargo.toml` 是项目的身份证兼总开关**。看到它就知道这是个 Rust 项目；依赖、版本、edition 都在这里声明。Cargo 一个工具包办了依赖管理和构建两摊事，不需要另找构建工具。
2. **编译是必经步骤，没有"零构建"选项**。Rust 源码必须先编译成机器码才能跑，不存在"直接运行源文件"——`cargo run` 就是把"编译 + 运行"并成一条命令。开发用默认的 debug 编译（快），发布用 `--release`（编译慢得多，但运行性能差距巨大）。
3. **产物是独立二进制文件**。`cargo build --release` 之后，`target/release/` 下就是一个不依赖任何运行时的可执行文件，拷到同系统的机器上就能跑——所谓"单二进制分发"不是什么黑科技，是编译型语言的天然形态。

这套骨架同样值得记熟：**AI 生成 Rust 项目时，默认产出的就是 `Cargo.toml` + `src/main.rs`**。验收动作也很固定：`cargo run` 能不能跑、`cargo test` 过没过。而且 Rust 项目"能编译通过"本身就说明了一半质量——借用检查器已经替你把过关了。

## 六、因果链小结

```text
系统编程要性能,内存漏洞却占严重漏洞七成 → 不能靠程序员自觉
GC 能保证安全,但停顿和开销进不了内核     → 不能靠运行时兜底
只剩一个位置放得下安全保障:编译期        → 有了所有权系统(2010-2015)
语言剧变无人敢用,工具链碎片化劝退        → 1.0 稳定承诺 + Cargo,工业化起飞(2015-)
```

## FAQ

约定：问答随实际疑问追加，每条几句话内。

**Q1：Cargo 具体是什么？**
Rust 装好后自带的命令行工具，包管理器 + 构建工具二合一。对照 JS 世界：`Cargo.toml` ≈ `package.json`，crates.io ≈ npm registry，`cargo build/test/run` ≈ `npm run build/test`，rustup（管工具链版本）≈ nvm。它的重要性在于：C/C++ 几十年没有官方包管理器，Cargo 把这块空缺直接填平了。

**Q2：tsgo 和 Rust 什么关系？**
tsgo 是微软用 Rust 重写的 TypeScript 编译器（名字是 "TypeScript, go!" 的意思，不是 Go 写的），速度约为原版 tsc 的 10 倍，未来将成为 TypeScript 7。它是"Rust 反向渗透 JS 工具链"浪潮中的代表，和 SWC、Biome 同一批。

**Q3：为什么新一代 JS 工具链都选 Rust，不选 Go？**
共性需求有三：单二进制分发（以 npm 包外壳发布预编译产物）、解析检查的极致性能、内存安全（开发工具经常处理来路不明的代码）。Go 也快（esbuild 就是 Go 写的），但 GC 带来的延迟抖动和内存安全叙事让 Rust 成为这类工具的默认答案。

**Q4：Rust 和 Go 是什么关系？**
几乎同年起步（2009 前后），针对同一批上一代语言的顽疾，给出了相反答案：Go 选"简单 + GC + 编译快"，牺牲性能上限换开发效率；Rust 选"安全 + 零开销"，牺牲学习曲线换性能底线。两个都活了下来：Go 吃下云基础设施和后端服务，Rust 吃下内核、高性能工具。详细对比另行成文。

**Q5："和借用检查器搏斗"到底是什么体验？**
你写了段在别的语言完全合法的代码，Rust 编译器拒绝通过——比如把一个值传给别人之后自己还在用。它本质是在逼你提前回答"谁拥有这个数据、借出去还能不能改"。痛苦集中在前几个月，之后这些约束会变成设计直觉。
