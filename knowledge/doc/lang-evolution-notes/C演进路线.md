# C 演进路线

一句话版：**操作系统只能用汇编写，换个机型就得整段重写；Bell 实验室造出贴近硬件又可移植的 C 并用它重写 UNIX，从此"编译器先过去、操作系统跟过去"，C 统治系统编程五十年，成了几乎所有主流语言的语法祖先。**

## 一、UNIX 被汇编锁死（1969-1973）

1969 年，Ken Thompson 和 Dennis Ritchie 在 Bell 实验室写 UNIX，用的是 PDP-7 的汇编——每行指令都焊死在具体机型上，换机器就整个重写。Thompson 先按 BCPL 的思路造了无类型的 B 语言，但 B 按机器字寻址，而新机器 PDP-11 按字节寻址，B 水土不服。

Ritchie 的改造就是 C 的诞生（1972-1973）：给 B 加上类型（char/int/指针），指针直接对应内存地址。1973 年 UNIX 内核用 C 重写——**操作系统第一次主要用高级语言写成**。意义在可移植性：把 UNIX 搬到新机器不再需要重写系统，只需要给新机器写一个 C 编译器。此后硬件公司每出一种新 CPU 都顺手配 C 编译器，滚雪球就此开始。

C 的设计立场由此定死：**贴硬件（指针、手动内存、无运行时），但源代码可移植**。外号"可移植汇编"——写的是高级语言，编译出来贴近手写汇编的效率。

## 二、标准化（1978-1990）：K&R 与"信任程序员"

1978 年 Kernighan 和 Ritchie 出版《The C Programming Language》（K&R），成为事实标准。但书没规定的行为——数组越界之后发生什么、有符号数溢出之后发生什么——各家编译器自行其是，程序换个编译器就变脸。

1989 年 ANSI 出台标准（C89，次年 ISO 采纳称 C90）。但标准选择了一条至今未变的哲学：**把这类行为留成"未定义"（Undefined Behavior），不检查、不兜底**——数组不查越界，指针不查空，类型转换全凭程序员自觉。理由是性能与自由：C 生来要写操作系统内核，任何运行时检查都是不可接受的税。

这个选择是 C 五十年统治力的根，也是 Rust 篇那条统计（约 70% 严重安全漏洞是内存错误）的因——**自由与漏洞同源**。C 后来的版本（C99/C11/C17/C23）只做温和增补，从未动这个内核哲学，与 Go 的"不加什么也是决策"遥相呼应：C 连补课都几乎不上，课全让后代上了。

## 三、帝国与后代（1980s-今）

C 的帝国不用抢，是"底层"本身：UNIX 家族全部（包括 1991 年 Linus 用 C 写的 Linux）、Windows 内核的大量代码、几乎所有嵌入式设备、数据库内核（SQLite）、解释器内核（Python 的 CPython 是 C 写的；JS 的 V8 是 C++，见姊妹篇）。你在任何语言里写代码，脚下踩的多半是 C/C++。

同样重要的是后代：C++（1985，见姊妹篇）、Objective-C（1984，后来的 iOS 开发）、以及语法上的孙辈 Java/C#/JavaScript——花括号、分号、if/while 这副面孔，是 C 留给全行业的基因。GCC（1987，Stallman）让"每个平台都有免费 C 编译器"从滚雪球变成雪崩。

## 四、三个必要词汇

- **指针**：存内存地址的变量。`&` 取地址、`*` 解引用；数组本质上是指针的语法糖；`malloc/free` 手动管理堆内存。C 全部的自由和全部的危险，源头都在这里。
- **未定义行为（UB）**：标准故意不规定的行为（越界读写、空指针解引用、有符号溢出）。不是疏漏是设计——编译器据此做激进优化，代价是出错时没有兜底，程序"看起来能跑"地错下去。
- **一次编写、到处编译**：Java 的口号是"到处运行"（字节码+VM），C 的可移植性在源代码级——同一份 .c，每个平台各自编译成本地机器码。两种"可移植"，一个在运行时，一个在编译期（呼应 Java 篇）。

## 五、工程化：一个 C 项目怎么构建和运行

```text
写 .c/.h 源文件
gcc main.c -o app     → 编译+链接一步出可执行文件
./app                 → 运行
make                  → 多文件项目:Makefile 写好规则,一条命令增量构建
cmake -B build && cmake --build build → 跨平台大项目的标准姿势(CMake 生成构建文件)
测试:assert / unity / CTest
```

三个关键认知：

1. **没有官方包管理器，这是 C 生态最大的"古代特征"**。依赖靠系统包管理器（apt/brew）、源码 vendoring 或子模块；清单文件也不存在——Makefile/CMakeLists.txt 是构建脚本，不是 npm 意义上的依赖清单。
2. **编译必经**，产物是原生二进制——速查表那条分水岭（构建是否必经）里，C 和 Rust/Go 同侧。
3. **AI 验收三连**：`gcc main.c -o app && ./app` 跑通、`make` 全量构建通过、测试（若有）通过。AI 生成 C 项目时，默认给的就是 main.c + Makefile 这副骨架。

## 六、因果链小结

```text
操作系统被汇编写死在机型上    → 有了 C(1972,贴硬件但可移植),UNIX 随之重写
各家编译器行为不一          → ANSI C(1989),"信任程序员"哲学定稿
底层世界需要稳定的通用语     → 帝国=操作系统/嵌入式/万物内核;C++/ObjC/Java/C#/JS 皆其后裔
```

## FAQ

约定：这里的问答随实际疑问追加，每条回答控制在几句话内；问题来自真实使用中的困惑，不预设。

**Q1：C 和 C++ 什么关系？**
C++ 诞生时是"带类的 C"，能直接链接 C 库、C 程序员零成本转岗；但今天它们是两门独立语言，各自标准化、各自演进。选型直觉：要抽象和生态上 C++，要极简和稳定上 C。

**Q2：2026 年了为什么还要学 C？**
两个理由：一是它守着的底层（内核、嵌入式、其他语言的运行时）五十年没换过主人；二是 C 是"计算机到底怎么工作"的最佳载体——指针、内存、栈堆，见过没包装的机器，才算真的懂机器。

**Q3：为什么 C 程序老报段错误（Segmentation Fault）？**
"信任程序员"哲学：越界、野指针、重复释放，运行时一律不拦，直到碰进操作系统划的禁区才当场击毙。这类错误正是 Rust 的靶子（见 Rust 篇）。

**Q4：C 有垃圾回收吗？**
没有，也不打算有。malloc 手动申请、free 手动释放：漏了是内存泄漏，早了是悬垂指针。Rust 的所有权机制，就是冲着这套手动纪律来的。
