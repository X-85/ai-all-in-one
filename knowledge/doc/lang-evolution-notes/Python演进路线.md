# Python 演进路线

一句话版：**ABC 教学语言可读但封闭，C 太重、Shell 太弱，所以有了 Python 当"胶水"；生态滚大后语言却分裂成 2/3 两个世界，拖了十二年才统一；最后不是语言变强了，是 NumPy/PyTorch 们把它抬上了 AI 时代的王座。**

> 类型：语言 | 生态：AI 与科学计算 | 诞生：1991

姊妹篇：[JS-Node-TS演进路线](JS-Node-TS演进路线.md)、[Rust演进路线](Rust演进路线.md)。Python 这条的特殊之处：决定它命运的关键转折大多不在语言内部，而在生态卡位。

配套速查（pip/uv/pytest 等工具命令）：[构建工具链速查](构建工具链速查.md)

## 一、诞生（1989-1991）：ABC 的教训与胶水语言

1989 年圣诞假期，荷兰 CWI 研究所的 Guido van Rossum 开始写一门新语言（名字来自 Monty Python 喜剧团，不是蟒蛇），1991 年首次发布。

出发点是他参与过 ABC 教学语言的教训：ABC 可读性极好、非专业的人也能上手，但它是个封闭系统——难扩展、和操作系统脱节、没有生态，教完算法就到头了。而另一头的现实是：用 C 写真东西太重（手动管内存、编译链接），Shell 脚本又够不着复杂逻辑。

Python 的定位就是取两头之长：**ABC 的可读性 + C 的扩展口**（可以用 C 写库给 Python 调用）。这个定位后来有个名字——**胶水语言**：自己不追求最快最强，负责把系统调用、C 库、各种组件粘起来。Guido 的哲学是"什么都做不到最好，但什么都顺手"——谁都愿意用它，这为几十年后的生态爆发埋了种子。

## 二、分裂与统一（2008-2020）：Python 2/3 之痛

到 2000 年的 Python 2.0 时代，语言已经流行，但早期设计的历史欠账还在：字符串编码混乱、`print` 是语句不是函数、整数除法反直觉等。

2008 年社区决定偿还：发布 Python 3.0，**改正错误不惜断掉兼容**——`print` 变成函数、字符串默认 Unicode。结果是生态一刀两断：库作者要同时维护两个版本，企业的存量代码迁不动，Python 2.7 一直维护到 **2020 年才停止支持**——整整十二年，两个世界并存。

三条演进路线在这里可以互相照亮：

| 路线 | 兼容哲学 | 结局 |
|------|---------|------|
| Python 3 | 敢断，硬切换 | 痛十二年，教训刻进社区基因 |
| Rust 1.0 | 承诺不断 | 工业化起飞 |
| JS / ES6 | 只加不断 | 旧代码照跑，新特性渐进普及 |

**兼容性是语言的生死线**——这个教训直接塑造了后来 Python 的一切大动作（包括类型注解为什么走渐进式，见第四节）。

## 三、AI 时代的王座（2006-今）：生态抬上去的

Python 登顶的关键转折不是语言变了，而是**生态集体卡位**：

- NumPy（2006）打下科学计算地基 → pandas（2008）数据处理 → scikit-learn（2011）机器学习 → Jupyter（2015）交互式笔记本成为学界标配；
- TensorFlow（2015）、PyTorch（2016）相继把 **Python 定为官方门面语言**——模型用 C/C++/CUDA 写，但操作它们的接口是 Python。

为什么大家都选它？胶水定位的兑现：研究人员要的是"下午就能上手、试错快"，性能敏感的部分早就下沉到 C/CUDA 底座，CPython 只当遥控器。于是"什么都第二好"兑现成"AI 时代的拉丁语"——学界通用语。

对选型的意义一句话：**选 Python 选的是生态，不是语言。** 它的地位问题从来不在语言层，动不动拿"Python 慢"否定它，等于没看懂它坐在哪。

## 四、现代化补课（2014-今）：王座坐稳后还的三笔债

生态赢了之后，语言自身的历史欠账开始集中偿还，三条线并行：

1. **类型注解（PEP 484，随 3.5 发布）**：工程变大后动态类型难维护，同一个病 JS 得过，Python 的解法是**渐进式**——注解可加可不加、运行时不强制，由 mypy/pyright 这类工具单独检查。比 TS 更温和，因为 Py2/3 的教训摆在那：不敢再来一次强制切换。
2. **性能与 GIL**：CPython 的"慢"有个标志性根源——**GIL（全局解释器锁）**，同一时刻只允许一个线程执行 Python 代码，多线程用不上多核。补课进行中：3.11（2022）官方提速约 25%，3.13（2024）推出实验性的无 GIL 版本。但要记得：AI 场景的重活本来就在 C/CUDA 里，GIL 经常不挡路。
3. **打包（四十年之痒）**：从 setup.py 到 pip、virtualenv/conda，再到 2016 年标准化的 `pyproject.toml`，2024 年 Rust 写的 **uv** 把装依赖提速十倍以上——Python 公认的历史欠账就是打包，至今仍在收敛。这也是"Rust 重写各生态工具链内核"浪潮的最新一站。

## 五、三个必要词汇

- **胶水语言**：Python 的定位而非贬义——自己当控制台，粘合 C/C++ 高性能组件。一切的起点和终点。
- **GIL（全局解释器锁）**：CPython 同一时刻只放行一个线程，多线程用不了多核。Python"慢"的标志性原因，也是它多进程文化的来源。
- **虚拟环境（venv）**：每个项目一个独立的依赖隔离空间。Python 工程化的第一纪律——JS 的 `node_modules` 天然按项目隔离，Python 不建 venv 就会把所有项目的依赖装成一锅粥。

## 六、工程化：一个 Python 项目怎么构建和运行

安装 Python 自带解释器和 pip。现代项目的标准流程：

```text
python -m venv .venv       → 建虚拟环境(本项目独立的依赖空间)
source .venv/bin/activate  → 激活(Windows: .venv\Scripts\activate)
pip install requests       → 装依赖(记录进 requirements.txt / pyproject.toml)
写代码                     → main.py 或 src/ 下的 .py 文件
python main.py             → 直接运行,没有构建步骤
pytest                     → 跑测试
```

三个关键认知：

1. **先建 venv 再装依赖，是 Python 的第一纪律**。不隔离的话依赖装进系统全局，项目之间版本互相打架。新一代工具 uv 一条 `uv init` 就能建好环境和依赖清单，把这套动作压缩到秒级。
2. **没有构建步骤**。和 JS 后端同属解释执行，改完就跑；新版清单文件是 `pyproject.toml`，正在取代老的 `requirements.txt`。
3. **"慢"经常不成立**。数值计算的活是 NumPy/PyTorch 在 C/CUDA 里干的，Python 只发号施令——验收 AI/数据项目时别被"Python 慢"吓住。

**AI 生成 Python 项目的默认骨架**：`pyproject.toml`（或 `requirements.txt`）+ `main.py`/`src/` + 虚拟环境。验收三连：装依赖 → `python main.py` 跑起来 → `pytest` 过。

## FAQ

约定：问答随实际疑问追加，每条几句话内。

**Q1：为什么 AI/科学计算用 Python，不用更快的语言？**
研究人员要的是上手快、试错快；真正的计算在 NumPy/PyTorch 的 C/CUDA 底座里，Python 只当控制台。而且数据格式、教程、同行代码全在 Python，换语言等于离开群落——生态比语言快慢重要得多。

**Q2：Python 2 到 3 为什么拖了十二年？**
Python 3 不兼容 2，而 2 的存量代码和库太庞大；库作者被迫同时维护两版，用户没动力先动，僵局直到 2020 年 Python 2 停止维护才解开。教训：兼容性是语言的生死线——这也是后来类型注解选择渐进式的原因。

**Q3：uv 是什么？**
2024 年发布的 Python 包管理器，Rust 写的，比 pip 快十倍以上，命令用法兼容。它是"Rust 重写各生态工具链内核"浪潮（JS 界的 tsgo/esbuild/Biome）在 Python 界的代表。

**Q4：Python 的类型注解和 TS 是什么关系？**
治同一个病（工程变大后动态类型难维护），路线不同：TS 是"超集语言 + 编译期剥类型"，Python 是"内置注解 + 渐进式"——可加可不加、运行时不强制，由 mypy/pyright 单独检查。温和路线是被 Py2/3 分裂吓出来的。

**Q5：GIL 到底锁住了什么？**
CPython 里同一时刻只有一个线程能执行 Python 字节码，所以多线程加速不了纯 Python 计算（IO 等待时锁会释放，所以爬虫类任务多线程仍有用；纯计算用多进程绕开）。3.13 起有无 GIL 的实验版本，生态适配还需时间。

**Q6：文中说的 ABC 语言是什么？**
Guido 在 CWI 参与实现过的教学语言（1980 年代，Geurts/Meertens/Pemberton 设计），目标是取代 BASIC、让非专业的人也写得出可读的真程序。Python 的招牌几乎全是继承它的：冒号 + 缩进定义代码块、if/elif/else、无类型声明、交互式解释器。它死于封闭——难扩展、够不着操作系统和文件；**ABC 的死因清单就是 Python 的需求文档**：可读性照单全收，再补一个 C 扩展口。
