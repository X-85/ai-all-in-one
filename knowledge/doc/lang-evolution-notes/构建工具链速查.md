# 构建工具链速查

这是一张**查表，不是教程**：只回答"哪个命令干什么、哪个文件是什么"。每种语言为什么诞生、工具为什么长成这样，见各篇演进路线（本目录内姊妹篇互链）。

## 一、总表

| 生态 | 清单文件 | 包管理器 | 装依赖 | 运行 | 构建 | 测试 | 产物 |
|------|---------|---------|--------|------|------|------|------|
| **JS** | `package.json` | npm | `npm install` | `node x.js` / `npm run dev` | 可选（esbuild/Vite，前端必选） | `npm test`（vitest / node --test） | 解释执行无产物；前端打包出静态文件 |
| **TS** | 同 JS | 同 JS | 同 JS | 传统：先 `tsc`/`tsgo` 编译再 `node` 跑；新版 Node 可直接跑可擦除语法的 TS | 同上 | 同 JS | 同 JS |
| **Rust** | `Cargo.toml` | cargo | `cargo add xxx` | `cargo run`（编译+运行一步） | `cargo build --release`（**必经**） | `cargo test` | 独立二进制，在 `target/release/` |
| **Go** | `go.mod` | go 命令本身 | `go get` / `go mod tidy` | `go run main.go` | `go build`（**必经**） | `go test` | 独立二进制 |
| **Python** | `pyproject.toml`（新）/ `requirements.txt` | pip / uv | `pip install xxx` | `python main.py` | 无（解释执行） | `pytest` | 无产物（`__pycache__` 只是缓存） |
| **Next.js**（React 框架，npm 生态） | `package.json` | npm | `npm install` | `npm run dev` / `npm run start` | `npm run build`（**必经**） | 默认未配，常配 vitest + playwright | `.next/`，由 Node 常驻伺候；`output: 'export'` 可退为纯静态 |
| **Vue**（渐进式前端框架，npm 生态） | `package.json` | npm | `npm install` | `npm run dev`（Vite，默认 5173） | `npm run build`（**必经**） | 脚手架创建时可选配 vitest + playwright（`npm run test:unit`） | `dist/` 纯静态文件，任何静态服务器/CDN 可伺候；SSR/全栈上 Nuxt |
| **React**（视图库，npm 生态） | `package.json` | npm | `npm install` | `npm run dev`（Vite，默认 5173） | `npm run build`（**必经**） | 默认未配，常配 vitest | `dist/` 纯静态文件；路由用 react-router，SSR/全栈上 Next.js |
| **C#** | `MyApp.csproj`（SDK 风格） | dotnet + NuGet | `dotnet add package xxx` | `dotnet run`（编译+运行一步） | `dotnet build`（**必经**，run 内置） | `dotnet test`（xUnit/NUnit） | 可执行产物；`dotnet publish` 可出自包含包（连运行时一起） |
| **C** | 无（Makefile/CMakeLists 是构建脚本） | 无官方，靠系统包管理器 | apt / brew 等 | `./app` | `gcc main.c -o app`（**必经**） | CTest / unity / assert | 独立二进制 |
| **C++** | 无（CMakeLists.txt） | conan / vcpkg（第三方） | `conan install` 等 | `./app` | g++ 或 CMake（**必经**） | gtest / catch2 + CTest | 独立二进制 |
| **SQL** | 无（schema 迁移由工具管） | 无 | — | psql 等客户端交互 | 无 | dbt 测试 / 应用集成测试 | 无产物（数据与 schema 在数据库服务器上） |
| **Spring Boot**（Java 框架，Maven 生态） | `pom.xml` | mvn + Maven 中央仓 | 随构建自动解析 | `./mvnw spring-boot:run`（内嵌 Tomcat） | `./mvnw clean package`（**必经**） | `./mvnw test`（JUnit） | 可执行 fat jar（`target/`，`java -jar` 直接跑） |
| **Django / Flask / FastAPI**（Python Web 三代，pip 生态） | 同 Python（`pyproject.toml`） | 同 Python | 同 Python | `python manage.py runserver` / `flask run` / `fastapi dev` | 无（解释执行） | pytest | 无产物；生产由 uvicorn / gunicorn 伺候 |
| **Docker / K8s**（容器平台） | `Dockerfile` + 部署 YAML | 镜像仓库（Registry） | `docker pull` | `docker run` | `docker build`（**必经**） | CI 内集成测试 / 镜像内自测 | 镜像（可分发产物）；K8s 用 `kubectl apply` 声明式部署 |

## 二、每个生态的"三件套"

认出一个项目是什么生态，看清单文件就够了，它们总是成套出现：

| 生态 | 清单（身份证） | 锁文件（精确版本） | 依赖目录 |
|------|--------------|------------------|---------|
| JS/TS | `package.json` | `package-lock.json` | `node_modules/` |
| Rust | `Cargo.toml` | `Cargo.lock` | 编译时拉取，不落目录 |
| Go | `go.mod` | `go.sum` | 模块缓存在用户目录 |
| Python | `pyproject.toml` | 视工具而定（uv.lock 等） | `venv/`（虚拟环境目录） |

## 三、行间规律（选型时真正有用的三条）

1. **"构建是否必经"是分水岭**。解释执行的语言（JS 后端、Python）可以零构建，改完直接跑；编译执行的语言（Rust、Go）必须先编译。构建的代价换来的就是总表最后一列——**独立二进制 vs 无产物**。
2. **工具链可以换内核，外壳不变**。tsgo（Rust 写的 TS 编译器）、esbuild（Go 写的打包器）、uv（Rust 写的 Python 包管理器）都在证明同一件事：命令长得一样、位置一样，内核用谁写是性能问题，不是生态问题。
3. **AI 验收三连，任何生态通用**：装依赖 → 跑起来 → 过测试。即 `npm install && npm run dev && npm test`、`cargo run && cargo test`、`go run . && go test ./...`。让 AI 生成项目后，跑通这三条就算验收通过。

## 四、单个工具是谁

| 工具 | 一句话 |
|------|--------|
| **rustc** | Rust 编译器，语言本体的执行入口；平时不直接敲，都通过 cargo 调用 |
| **cargo** | Rust 项目管家：依赖管理 + 构建二合一 |
| **rustup** | Rust 工具链安装器/版本管理器（角色 ≈ nvm） |
| **npm** | Node 包管理器，装 Node 自带 |
| **tsc** | TypeScript 编译器：类型检查 + 剥类型，TS 写的，大项目慢 |
| **tsgo** | tsc 的 Rust 重写版（微软官方），约 10 倍速，未来是 TypeScript 7；名字意为 "TS, go!"，不是 Go 写的 |
| **esbuild / Vite** | JS 打包构建工具，前端场景必用；esbuild 是 Go 写的 |
| **create-next-app / next** | Next.js 官方脚手架 / 命令行；`next dev`、`next build`、`next start` 三个子命令覆盖全流程 |
| **create-vue / Vite** | Vue 官方脚手架 / 新一代构建工具（开发不打包、按需编译）；Vite 由 Vue 作者出品，现为全 JS 生态共用底座 |
| **create-react-app（CRA）** | React 旧官方脚手架，2023 年退役——新项目用 Vite 的 react 模板（`npm create vite -- --template react`）或 Next.js |
| **dotnet** | .NET/C# 项目管家 CLI：脚手架（new）+ 依赖（add package）+ 构建/运行/测试/发布一体 |
| **gcc / g++** | GNU 的 C / C++ 编译器；实际项目多经 make/CMake 间接调用 |
| **CMake** | C/C++ 事实标准的构建系统生成器：一份清单生成各平台的构建工程 |
| **psql** | PostgreSQL 官方命令行客户端：交互查询、执行脚本、看执行计划的入口 |
| **vitest / pytest** | JS / Python 的测试框架 |
| **mvn / mvnw** | Java 项目管家（Maven）：依赖+构建+测试一体；mvnw 是项目自带的版本锁定包装器，优先用它 |
| **Spring Initializr** | Spring Boot 官方脚手架（start.spring.io）：勾选 starter 生成骨架——手拼 pom 依赖版本是上个时代的工伤来源 |
| **django-admin / flask / fastapi** | Python Web 三代的官方入口：Django 建站+自带迁移与 Admin / Flask 三行起步的微内核 / FastAPI 自带交互文档 `/docs` |
| **docker / kubectl** | 容器与集群的两级界面：`docker build/run` 管单机镜像；`kubectl apply/get/logs` 对集群"提交声明、查看现实" |
