# 构建工具链速查

这是一张**查表，不是教程**：只回答"哪个命令干什么、哪个文件是什么"。每种语言为什么诞生、工具为什么长成这样，见两篇演进路线：[JS-Node-TS演进路线](JS-Node-TS演进路线.md)、[Rust演进路线](Rust演进路线.md)。

## 一、总表

| 生态 | 清单文件 | 包管理器 | 装依赖 | 运行 | 构建 | 测试 | 产物 |
|------|---------|---------|--------|------|------|------|------|
| **JS** | `package.json` | npm | `npm install` | `node x.js` / `npm run dev` | 可选（esbuild/Vite，前端必选） | `npm test`（vitest / node --test） | 解释执行无产物；前端打包出静态文件 |
| **TS** | 同 JS | 同 JS | 同 JS | 传统：先 `tsc`/`tsgo` 编译再 `node` 跑；新版 Node 可直接跑可擦除语法的 TS | 同上 | 同 JS | 同 JS |
| **Rust** | `Cargo.toml` | cargo | `cargo add xxx` | `cargo run`（编译+运行一步） | `cargo build --release`（**必经**） | `cargo test` | 独立二进制，在 `target/release/` |
| **Go** | `go.mod` | go 命令本身 | `go get` / `go mod tidy` | `go run main.go` | `go build`（**必经**） | `go test` | 独立二进制 |
| **Python** | `pyproject.toml`（新）/ `requirements.txt` | pip / uv | `pip install xxx` | `python main.py` | 无（解释执行） | `pytest` | 无产物（`__pycache__` 只是缓存） |

## 二、每个生态的"三件套"

认出一个项目是什么生态，看清单文件就够了，它们总是成套出现：

| 生态 | 清单（身份证） | 锁文件（精确版本） | 依赖目录 |
|------|--------------|------------------|---------|
| JS/TS | `package.json` | `package-lock.json` | `node_modules/` |
| Rust | `Cargo.toml` | `Cargo.lock` | 编译时拉取，不落目录 |
| Go | `go.mod` | `go.sum` | 模块缓存在用户目录 |
| Python | `pyproject.toml` | 视工具而定（uv.lock 等） | `venv/`（虚拟环境目录） |

## 三、行间规律（选型时真正有用的三条）

1. **"构建是否必经"是分水岭**。解释执行的语言（JS 后端、Python）可以零构建，改完直接跑；编译执行的语言（Rust、Go）必须先编译。构建的代价换来的就是总表最后一列——**独立二进制 vs 无产物**。
2. **工具链可以换内核，外壳不变**。tsgo（Rust 写的 TS 编译器）、esbuild（Go 写的打包器）、uv（Rust 写的 Python 包管理器）都在证明同一件事：命令长得一样、位置一样，内核用谁写是性能问题，不是生态问题。
3. **AI 验收三连，任何生态通用**：装依赖 → 跑起来 → 过测试。即 `npm install && npm run dev && npm test`、`cargo run && cargo test`、`go run . && go test ./...`。让 AI 生成项目后，跑通这三条就算验收通过。

## 四、单个工具是谁

| 工具 | 一句话 |
|------|--------|
| **rustc** | Rust 编译器，语言本体的执行入口；平时不直接敲，都通过 cargo 调用 |
| **cargo** | Rust 项目管家：依赖管理 + 构建二合一 |
| **rustup** | Rust 工具链安装器/版本管理器（角色 ≈ nvm） |
| **npm** | Node 包管理器，装 Node 自带 |
| **tsc** | TypeScript 编译器：类型检查 + 剥类型，TS 写的，大项目慢 |
| **tsgo** | tsc 的 Rust 重写版（微软官方），约 10 倍速，未来是 TypeScript 7；名字意为 "TS, go!"，不是 Go 写的 |
| **esbuild / Vite** | JS 打包构建工具，前端场景必用；esbuild 是 Go 写的 |
| **vitest / pytest** | JS / Python 的测试框架 |
