## 一、零开销抽象的誓言（1979-1985）

1979 年，Bell 实验室的 Bjarne Stroustrup 面对的处境：做分布式系统，Simula（1967 年第一个面向对象语言）的类、继承用着舒服，但编译慢、运行慢到没法忍；换 C，快，但没有抽象，大项目里裸写。他的誓言成了 C++ 的立国哲学——**零开销抽象（zero-overhead abstraction）：你没用到的抽象不付一分钱；用到的抽象，编译结果不逊手写 C。**

路径也由此决定：不造新语言，做"带类的 C"（1979 年从预处理器起步），1983 年更名 C++，1985 年首发商用版。**与 C 兼容**是胜负手：C 库直接链接，C 程序员一个文件一个文件地迁移，渐进采用。这是它后来工业胜利的根——也是一切债的根：C 的手动内存、裸指针、信任程序员哲学（见 C 篇），全套继承。

## 二、标准化与膨胀（1990-2011）：赢了工业，重了自己

C++98（ISO 首标）收录 STL（Stepanov 的容器/算法/迭代器库）和模板。模板很快被发现自己图灵完备——编译期就是一台计算机，元编程成为可能，报错信息也成为传说中的灾难（几千行模板错误里找第一因）。

九十年代到零零年代，C++ 拿下所有"性能天花板"场景：游戏引擎（Unreal）、浏览器（Chrome/Firefox）、数据库（MySQL）、Office、Photoshop、金融高频交易。企业应用层则被 Java（1995）整锅端走——**C++ 丢了企业，守住了性能天花板**，这个分工至今未变。

然后是空窗：C++98 之后下一个标准从 2000 年代拖到 2011 年才落地。空窗期语言膨胀失控，"世界上最复杂的语言"名号坐实；Go（2009）的诞生动机里，对 C++ 复杂度的反叛是明说的那条（见 Go 篇）。

## 三、现代 C++（2011-今）：三年一版地还债

C++11（2011）被公认为"现代 C++"起点，像一次分期还债：

- **智能指针**（unique_ptr/shared_ptr）还手动内存的债，裸 new/delete 退居二线；
- **move 语义**还无谓拷贝的债；
- **auto、lambda、range-for** 还表达力的债；
- **标准线程库**还"标准库不管并发"的债。

此后三年一版（C++14/17/20/23/26）：C++20 的 concepts 还模板报错地狱的债，ranges、协程陆续落地，模块开始还编译慢的债（进行中）。贯穿始终的正统姿势是 **RAII**——资源获取即初始化，析构函数确定性释放——它也是 Rust 所有权机制的直系前身：**Rust 把 RAII 从"程序员自觉"升级成"编译器强制"**（呼应 Rust 篇的错误左移）。

还没还的最大一笔债：内存安全。C++ 的答案是智能指针+编码指南，Rust 的答案是换一门语言——这笔债怎么收，是两条路线的分野。

## 四、三个必要词汇

- **RAII**：资源随对象生命周期自动管理——构造获取、析构释放。对比 GC 的不确定回收，RAII 是确定性的：离开作用域的瞬间释放。C++ 安全用资源的正统，所有权的直系前身。
- **零开销抽象**：不为用不到的特性付钱；用到的抽象编译后不逊手写。C++ 的立国哲学，也是模板复杂度的永久辩护词。
- **模板**：编译期泛型，且图灵完备——编译器在编译期就能"算"出代码。STL 是最大成就，元编程是深水区，报错是噩梦。

## 五、工程化：一个 C++ 项目怎么构建和运行

```text
写 .cpp/.hpp 源文件
g++ main.cpp -o app      → 编译+链接一步(单文件)
./app                    → 运行
cmake -B build && cmake --build build → 多文件项目标准姿势(C 与 C++ 共用)
ctest                    → 跑测试(gtest/catch2 挂在 CTest 上)
依赖:conan / vcpkg(第三方包管理器,官方至今没有)
```

三个关键认知：

1. **CMake 是事实标准**，C/C++ 共用（见 C 篇）：一份清单，生成各平台的构建系统。
2. **编译必经且出了名的慢**：头文件是文本复制粘贴，模板在每个用到它的文件里重新实例化，大项目里同一份代码被反复解析几百遍——Go 篇"45 分钟"的梗即来源于此；C++20 模块是解药，生态普及中。
3. **AI 验收三连**：单文件 `g++ main.cpp -o app && ./app` 跑通，或 CMake 全量构建通过；程序输出正确；ctest 过。AI 生成 C++ 项目时，默认给的就是 main.cpp + CMakeLists.txt 这副骨架。

## 六、因果链小结

```text
Simula 太慢,C 太裸              → "带类的 C"(1979),零开销抽象立誓(1985 发布)
兼容 C = 渐进采用 + 全套继承      → 赢了工业(游戏/浏览器/数据库),企业层输给 Java
标准空窗,复杂度失控              → 现代 C++(2011 起)三年一版还债;内存安全留给 Rust
```

## FAQ

约定：这里的问答随实际疑问追加，每条回答控制在几句话内；问题来自真实使用中的困惑，不预设。

**Q1：C++ 是 C 的超集吗？**
口号上是，实际不是——有少量不兼容（如 C 的隐式 void* 转换在 C++ 里不合法）。今天的共识：两门独立语言共享 C 的语法基因；C++ 能直接链接 C 代码，但别指望把任意 .c 当 .cpp 编译。

**Q2：学 C++ 之前要先学 C 吗？**
不必，甚至可能先学出坏习惯（裸 malloc、裸指针）。现代教学直接从 C++ 起步，RAII 和智能指针优先；真要写内核、嵌入式，再回头学 C。

**Q3：Rust 会取代 C++ 吗？**
在"新写的、内存安全敏感的项目"里在抢；但 C++ 守着天文数字的存量代码和性能天花板场景，长期是共存格局。Chrome 和微软那两个"约 70% 严重漏洞是内存错误"的统计，样本正是 C++ 代码库——这也是 Rust 篇的起点。

**Q4：为什么 C++ 编译这么慢？**
头文件是文本级的复制粘贴，模板又要在每个用到它的翻译单元里重新实例化，同一份代码被反复解析。模块（C++20）从根上改这个模型，但生态普及还需数年。
