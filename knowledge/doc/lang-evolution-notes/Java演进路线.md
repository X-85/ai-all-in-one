# Java 演进路线

一句话版：**1995 年"一次编写、到处运行"的承诺让 Java 靠浏览器烟花起飞；浏览器梦碎后它转向企业服务器扎根，配置地狱逼出 Spring 民间造反；语言被嘲笑僵化二十年，Java 8 用 lambda 补课、此后半年一版还债——如今靠"20 年不破兼容"统治企业层。**

> 类型：语言 | 生态：企业信息化 + Android | 诞生：1995

配套速查（mvn/gradle/junit 等工具命令）：[构建工具链速查](构建工具链速查.md)

## 一、诞生（1991-1996）：机顶盒失败，浏览器烟花，留下了 JVM

1991 年 Sun Microsystems 的"Green 计划"里，James Gosling 给机顶盒和交互式电视写了一门语言，叫 Oak。目标市场的算盘是：家电设备芯片五花八门，写一次到处跑才有救。结果机顶盒市场没起来，Oak 眼看要死。

1995 年转向：改名 Java（咖啡豆的灵感，Logo 就是咖啡杯），搭上互联网快车，靠浏览器插件 Applet 演示"网页里跑程序"，一夜爆红。口号是 **Write Once, Run Anywhere（一次编写，到处运行）**——技术上就是把代码编译成**字节码**，跑在一个各平台都实现的虚拟机 **JVM** 上，绕开 C++ 按平台编译 N 份的死路。

烟花很快放完：浏览器大战、安全问题、Flash 的冲击，Applet 十几年后彻底退场。**但那台 JVM 和这门语言活了下来**——GC 从第一天就内置、不用手动管内存、多线程内建，这套底子在 1995 年是降维打击。

一个著名伏笔：同年网景把 LiveScript 改名 JavaScript，纯粹蹭 Java 的热度——两门语言没有血缘，这是 FAQ 的必答题。

## 二、转向与帝国（1998-2010）：企业服务器扎根，Spring 民间造反

浏览器梦碎，Java 找到了真正的主场：**服务器**。1998 年的 Java 2 把家族分成三支（J2SE 桌面 / J2EE 企业 / J2ME 嵌入式），Servlet/JSP 打开服务端大门，银行、电信、政府的信息化浪潮把 J2EE 变成了企业级标准——帝国第一根柱子是**企业信息化**。

但官方方案 EJB 走火入魔：写个 Hello World 要五六个类加一堆 XML 配置，人称"配置地狱"。2002 年，Rod Johnson 出书造反，2004 年 **Spring** 框架 1.0 发布——用依赖注入把对象组装变成声明式，轻量、可用。民间方案干翻了官方方案，Spring 从此成为 Java 的事实标准。

帝国第二根柱子是意外：**Android（2008）选 Java 语法作为官方开发语言**（跑在 Google 自家的虚拟机上），移动时代给 Java 又续了一个帝国。

2010 年 Oracle 以 74 亿美元收购 Sun 接盘 Java，随后的十年版权官司（Oracle 诉 Google）反而证明了它的分量。关键决策是 Sun 留下的：**2006 年开源的 OpenJDK**——Java 从此有官方开源实现，谁也掐不死它。

顺便把 Go 篇那张兼容哲学表补上第五行：**Java——1996 年承诺至今，承诺得最早、守得最久，20 年前的字节码今天还能跑。这个兼容神话正是它统治企业层的根。**

## 三、现代化补课（2014-今）：僵化二十年后追上来

2004 到 2014 这十年是 Java 最被嘲笑的时期：C# 有 lambda 它没有，动态语言骂它啰嗦，"随便一个类名都有 30 个字母"（Spring 真有个类叫 `AbstractSingletonProxyFactoryBean`）。然后三步追上来：

1. **Java 8（2014）：lambda + Stream + 新日期 API**——函数式编程进场，相当于 Java 的 ES6 时刻。骂声最大的"语法化石"问题就此翻篇；
2. **发布节奏改革（2017 起）：每六个月一个版本**——不再憋大招，学习 Python 的版本紧迫感。企业只追 LTS 长期支持版（8、11、17、21、25），这套版本纪律成了 Java 的实用常识；
3. **虚拟线程（Java 21，2023）**：JVM 调度的轻量线程，KB 级起步、百万并发可行——补的正是 Go 篇 goroutine 的那门课，只是保留了原有 Thread 的用法形状，老代码不重写就能受益。

同期 JVM 侧还有持续的硬实力：G1 之后 ZGC 把垃圾回收停顿压进毫秒级，大数据全家桶（Hadoop/Kafka/Spark）全建在 JVM 上。**Java 慢、内存大的老印象，如今只剩"写起来啰嗦"一条还算成立。**

## 四、三个必要词汇

- **JVM**：Java 虚拟机，跑字节码的运行时。真正的遗产——语言和运行时彻底分离，同一台 JVM 上住着 Java/Kotlin/Scala/Groovy/Clojure 一家子。三层模型（语言/运行时/场景）的教科书案例。
- **Spring**：事实标准框架，"企业 Java"的同义词。今天说"会 Java"，默认约等于"会 Spring"。
- **LTS**：长期支持版本（8/11/17/21/25）。Java 半年一版，但企业生产环境只追 LTS——看 Java 项目先看它钉在哪个 LTS 上。

## 五、工程化：一个 Java 项目怎么构建和运行

安装的是 **JDK**（开发工具包 = 编译器 javac + 运行器 java + JVM，一个包全家桶）。现代标准流程：

```text
mvn archetype:generate     → 生成项目骨架(或者直接用 Spring Initializr 网页勾选)
写代码                     → src/main/java 下的 .java 文件,依赖声明在 pom.xml
mvn package                → 编译打包出 jar(构建必经)
java -jar target/app.jar   → 运行(Spring Boot 应用内嵌了服务器,一条命令起服务)
mvn test                   → 跑测试(JUnit)
```

三个关键认知：

1. **构建双雄垄断**：Maven（`pom.xml`）和 Gradle（`build.gradle`），声明依赖 + 构建二合一——这套路数比 npm 和 cargo 都早，是它们的祖师爷。几乎没有第三选择，看到 pom.xml 就知道是 Java 系项目。
2. **产物是字节码 jar，不是机器码**：和 Go/Rust 的单二进制恰好相反——jar 需要 目标机器装有 JVM 才能跑。"到处运行"的另一面就是"到哪都得带运行时"。
3. **企业 Java ≈ Spring Boot**：一个 `main` 方法加 `@SpringBootApplication` 注解，`java -jar` 直接起 Web 服务（Tomcat 内嵌，不用装）。AI 生成的默认骨架：`pom.xml` + `src/main/java/.../Application.java` + `application.yml`。

**验收三连**：`mvn package` 打得出 → `java -jar` 跑得起 → `mvn test` 过得了。


## FAQ

约定：问答随实际疑问追加，每条几句话内。

**Q1：Java 和 JavaScript 什么关系？**
没有血缘。1995 年网景把 LiveScript 改名 JavaScript，纯粹蹭 Java 热度（JS 篇第一节埋的伏笔）。一个是 Sun 的企业级语言，一个是网景的浏览器脚本，设计哲学相反。唯一的共同点是名字，以及后来都跑在各自的虚拟机上。

**Q2：JVM 是什么？和 Java 什么关系？**
Java 虚拟机：把字节码翻译成各平台机器码的运行时。它是"语言与运行时分离"的教科书案例——同一台 JVM 上住着 Java、Kotlin、Scala、Groovy、Clojure。Java 这门语言的真正遗产不是语法，是 JVM。

**Q3：为什么银行、保险、政府还在用"老掉牙"的 Java？**
因为承诺：20 年前编译的字节码今天还能跑，兼容神话全业界最强；JVM 的性能、GC、监控生态深不见底；人才池最大，出了事有商业支持。企业选语言买的是确定性，不是新鲜感。

**Q4：Spring 是什么？**
事实标准框架。EJB 时代"写个 Hello 要五个配置文件"逼出的民间造反（2002 成书、2004 发布 1.0），核心是依赖注入——对象组装从 XML 地狱变成声明式。Spring Boot（2014）再砍一刀：约定优于配置、内嵌服务器、一个 jar 跑天下。

**Q5：Kotlin 和 Java 什么关系？**
同住 JVM 的姊妹语言（JetBrains 出品，2019 年起是 Android 开发首选）。这是"语言与运行时分离"的红利：Java 受兼容承诺约束不敢大改，就由 Kotlin 在同一运行时上试验现代语法（空安全、数据类、协程），Java 再逐步吸收（record、虚拟线程都有生态呼声的影子）。

**Q6：虚拟线程和 goroutine 什么关系？**
Java 21（2023）正式落地的轻量并发（Project Loom）：线程由 JVM 调度、KB 级起步，百万并发可行——解决的正是 Go goroutine 解决的问题。风格不同：Java 保留传统 Thread 的 API 形状让老代码受益，Go 用 channel 建了新模型。
