## 一、一篇论文（1970-1979）

1970 年代以前的主流是层次/网状数据库（如 IBM 的 IMS）：数据挂在树和指针网里，查东西要写程序一步步导航——查"北京客户的订单"，你得知道指针怎么走，换个问法就重写一遍程序。

1970 年，IBM 研究员 E.F. Codd 发表论文《大型共享数据库的数据关系模型》，思路是数学化的：**数据 = 关系（集合论里的表），查询 = 关系代数（选择/投影/连接）**。查询不再描述"怎么找"，只描述"要什么"——这是声明式的胜利宣言（几十年后 React 把同一招用在界面上）。

IBM 启动 System R 实验项目落地，1974 年 Chamberlin 和 Boyce 造出查询语言 SEQUEL（后因商标改称 SQL）——把关系代数包上近似英语的外壳：`SELECT ... FROM ... WHERE ...`。接下来的商战是传奇：Ellison 读到论文，1977 年创办公司（后来的 Oracle），1979 年抢在 IBM 之前卖出第一个商用关系数据库；IBM 自己的 DB2 到 1983 年才上市。**发明在 IBM，第一桶金在 Oracle**——论文公开的代价与红利。

## 二、标准与帝国（1986-2000s）

1986 年 ANSI 出台第一个 SQL 标准，此后滚动至今：SQL-92（奠基）、SQL:1999（递归查询）、SQL:2003（窗口函数——数据分析的核武器）、SQL:2016（JSON）、SQL:2023（图查询）。标准是普通话，各家产品说方言：Oracle、DB2、SQL Server（1989，微软）、MySQL（1995，开源，LAMP 时代的心脏）、PostgreSQL（Berkeley 的 POSTGRES 一脉，1996 年 SQL 化）。但没有第二门语言做到这个程度：**一个领域，所有产品，核心语法全通**。生态帝国表里，SQL 的帝国就是"数据的一切"。

另一条暗线同样重要：IBM 的 Jim Gray 在 1970 年代奠基事务思想（ACID 一词 1983 年提出）——BEGIN/COMMIT/ROLLBACK，银行转账的原子性。SQL 不只是查询语言，它是"数据可靠性"这套工程传统的载体。

## 三、被"取代"的二十年（2000s-今）

2000 年代末 NoSQL 浪潮兴起（Web 规模，Bigtable/Dynamo 两篇论文，MongoDB 2009），"SQL 已死"成了流行叙事：超大规模分布式场景里 join 和事务碍事，新产品接口五花八门。

然后剧情反转。2010 年代：NoSQL 产品一个个把 SQL 系接口加回来（Cassandra 的 CQL、MongoDB 的聚合管道与 SQL 接口）；Google Spanner 这样的新一代分布式数据库原生说 SQL；大数据栈（Hive、Spark、Trino、Snowflake、Databricks）兜兜转转，最后递到用户手上的接口全是 SQL；到了 AI 时代，人对模型说的最稳的一句话还是"帮我写条 SQL"。

根子在语言范式：**声明式 + 优化器**。你说"要什么"，代价优化器（1979 年 System R 的 Selinger 优化器奠基，五十年持续进化）决定索引怎么用、join 怎么排。硬件换了五轮，优化器跟着新硬件一直变强——同一条 SELECT，1985 年和 2026 年写法不变，跑法天差地别。**接口不变、实现自由进化**，这是 SQL 五十年不倒的真正原因，也是它给所有语言设计的启示。

方言碎片化是永远的债：分页这一个动作，MySQL 写 LIMIT、SQL Server 写 TOP、Oracle 写 ROWNUM——标准永远追着方言跑。

## 四、三个必要词汇

- **声明式 vs 命令式**：SQL、React 说"要什么"；C、Java 说"怎么做"。声明式把"怎么做"外包给系统（优化器/框架），换来的红利是：需求不变，实现可以无限进化。
- **关系 / join**：表 = 关系 = 集合（理论上行无序、无重复）；规范化（1NF/3NF）是用完整性换冗余的拆表工艺；join 是按键把拆开的表拼回来。
- **事务与 ACID**：原子（要么全成要么全不成）/ 一致 / 隔离（并发互不踩）/ 持久（提交了就不丢）。转账是经典例子：扣款和入账必须同一个事务。隔离级别是工程深水区。

## 五、工程化：SQL 怎么"构建和运行"

SQL 没有传统意义的构建流程，它嵌在宿主工程里：

```text
起数据库:docker run postgres(或本机安装)
psql -h localhost -U me -d mydb → 交互终端(mysql/sqlcmd 同理)
\i schema.sql                  → 执行脚本建表
SELECT ... / EXPLAIN SELECT ... → 查询 / 看执行计划(调优入口)
应用集成:数据库驱动或 ORM(SQLAlchemy/Prisma/Hibernate)
schema 变更:迁移工具(flyway/liquibase/prisma migrate)管版本历史
```

三个关键认知：

1. **SQL 的"工程化"主体是数据库和迁移脚本**，不是语言项目：没有清单文件、没有编译，被版本管理的对象是 schema 变更历史。
2. **方言是现实**：标准是普通话，落地必有方言；跨产品迁移时，方言差异是真实成本。
3. **EXPLAIN 是性能问题的第一现场**：声明式语言调优的对象不是代码写法，是执行计划——这是 SQL 与命令式语言工程习惯的最大分岔。

AI 验收三连：`docker run` 起库、schema.sql 建表成功、一条带 join 的 SELECT 返回预期行。AI 生成 SQL 项目时，默认给的就是 schema.sql + 迁移目录 + 一段连接代码。

## 六、因果链小结

```text
导航式数据库,换个问法就重写程序   → Codd 关系模型(1970),System R 与 SQL(1974),Oracle 抢跑商用(1979)
一个领域被一门语言统一            → 标准滚动 + 方言家族,帝国 = 数据的一切
NoSQL 喊"取代"二十年             → SQL 接口长回 NoSQL,大数据终点也是 SQL:声明式+优化器不可替代
```

## FAQ

约定：这里的问答随实际疑问追加，每条回答控制在几句话内；问题来自真实使用中的困惑，不预设。

**Q1：SQL 算编程语言吗？**
算，但是特殊的一类：声明式 DSL（领域专用语言）。配合递归 CTE 和存储过程它图灵完备，但它的力量不在通用计算，在"把'要什么'说清楚，把'怎么做'交给优化器"。

**Q2：NoSQL 不是要取代 SQL 吗？**
取代论流行于 2009-2015；现实是 NoSQL 产品纷纷长出 SQL 系接口，新一代分布式数据库原生 SQL。教训：存储范式可以变，声明式+优化器的接口红利太值钱，没人舍得丢。

**Q3：MySQL、PostgreSQL、SQL Server 是什么关系？**
SQL 方言家族的不同实现。MySQL（1995）以开源轻量拿下 Web 时代；PostgreSQL（Berkeley 一脉）以严谨和扩展性著称；SQL Server 是微软系。核心语法全通，方言细节各有各的。

**Q4：有了 ORM 还要学 SQL 吗？**
要。ORM 生成的是 SQL：复杂查询、执行计划、索引调优仍要手写和读 EXPLAIN；ORM 经典的 N+1 查询问题，本质就是"没看住生成的 SQL"。
