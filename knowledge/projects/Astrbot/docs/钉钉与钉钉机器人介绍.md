# 钉钉与钉钉机器人介绍

> 本文根据钉钉官网、钉钉开放平台、钉钉机器人页面及开放平台文档目录整理。
> 信息截至 2026-08-07。钉钉的产品名称、接口、权限和机器人能力会持续更新，实际开发时应以开放平台当前文档为准。

## 一句话定义

钉钉（DingTalk）是阿里巴巴集团打造的企业级智能移动办公平台，也是面向组织协同、企业服务和应用开发的数字化平台。

钉钉机器人不是一个单独的软件产品，而是一组运行在钉钉组织、群聊或应用场景中的自动化程序。它可以接收事件或用户消息，调用企业内部系统、数据库和 AI 服务，再通过钉钉消息、卡片或其他应用能力返回结果。

可以用下面的方式理解二者的关系：

```text
钉钉 = 面向企业组织的沟通、协作、办公和应用平台
钉钉机器人 = 接入钉钉消息与开放能力的自动化应用
```

## 钉钉是什么

钉钉把企业中的人员、组织、消息、审批、考勤、会议、文档、工作台、业务应用和数据连接起来，提供统一的工作入口。官网当前将钉钉描述为：

- 阿里巴巴集团打造的企业级智能移动办公平台；
- 数字经济时代的企业组织协同办公和应用开发平台；
- 面向 AI 时代的新生产力工具。

从使用者角度看，钉钉主要提供以下几类能力：

1. **组织与身份**：企业、部门、员工、角色、权限和通讯录。
2. **即时沟通**：单聊、群聊、DING、文件和消息触达。
3. **协同办公**：审批、考勤、日程、会议、任务、文档和表格等。
4. **企业应用**：工作台、微应用、行业应用和第三方应用。
5. **开放能力**：API、事件订阅、应用开发、连接器、互动卡片和机器人能力。
6. **智能化能力**：AI 助手、智能问答、知识库和面向业务流程的自动化能力。

因此，钉钉不只是即时通讯软件。它更接近“企业组织系统 + 协同办公 SaaS + 应用运行入口 + 开放 PaaS”的组合。

## 钉钉机器人是什么

钉钉机器人是钉钉中的自动化服务角色。它通常以一个机器人身份出现在群聊、单聊或应用中，由外部服务或企业自己的后端程序驱动。

一个典型机器人工作流如下：

```text
用户发送消息或业务系统产生事件
              |
        钉钉消息/事件通道
              |
     机器人服务接收并校验请求
              |
   业务逻辑、数据库、企业系统或 AI
              |
       返回文本、Markdown、卡片或动作
              |
        用户在钉钉中看到结果
```

机器人通常用于：

- 监控告警、发布通知、流水线结果和异常提醒；
- 企业内部知识问答、制度查询和流程导航；
- 请假、报销、审批、会议安排等流程自动化；
- 查询订单、库存、客户、项目和工单状态；
- 将 GitLab、GitHub、Jira、阿里云 Code 等第三方系统的事件推送到群聊；
- 通过 AI 模型实现自然语言问答、摘要、分类和智能助手。

钉钉机器人官方介绍页强调的能力包括智能对话、自动化流程、应用集成、数据分析、安全保障、定制化服务和全天候在线。需要注意的是，这些是机器人解决方案层面的产品描述；具体能否实现，取决于机器人类型、开放平台权限、企业系统接口和后端实现。

## 谁开发钉钉和钉钉机器人

钉钉由阿里巴巴集团打造并持续运营，具体产品和技术由钉钉团队负责建设。钉钉机器人属于钉钉开放能力的一部分：钉钉提供身份、群聊、消息、事件、API、应用和安全机制，企业或第三方开发者负责实现自己的机器人业务逻辑。

因此，开发主体要区分为两层：

| 层次 | 负责方 |
| --- | --- |
| 钉钉平台本身 | 阿里巴巴集团和钉钉团队 |
| 某个具体机器人 | 企业自建团队、第三方服务商或个人开发者 |

一个企业自己开发的机器人，并不意味着它由阿里巴巴开发。阿里巴巴提供的是机器人运行所依赖的平台和开放接口。

## 起源和发展过程

### 起源

钉钉的产品背景是企业在移动互联网时代面临的沟通效率低、信息分散、组织管理成本高和办公系统彼此割裂等问题。公开资料通常将钉钉的早期起点描述为阿里巴巴内部用于提升组织沟通效率的项目，之后逐步产品化并面向企业市场。

从产品逻辑看，钉钉的演进不是单纯从“聊天工具”增加办公功能，而是围绕企业组织关系逐步扩展：先解决人和人的沟通，再连接组织流程、业务应用和企业数据。

### 发展阶段

| 阶段 | 主要方向 | 说明 |
| --- | --- | --- |
| 早期阶段 | 企业即时沟通和移动办公 | 以组织通讯录、单聊、群聊和移动办公为基础，降低企业沟通成本。 |
| 协同办公阶段 | 审批、考勤、会议、任务和文档 | 将高频办公流程放入统一入口，减少电话、邮件和纸质流程的分散。 |
| 平台开放阶段 | 微应用、API、工作台和应用市场 | 允许企业和服务商在钉钉中开发、发布和运行业务应用。 |
| 生态连接阶段 | 连接器、第三方系统和行业方案 | 将研发、客服、项目、财务、供应链等外部系统与钉钉连接。 |
| 智能化阶段 | AI 助手、机器人、知识库和互动卡片 | 从“消息通知”发展到理解意图、调用业务能力和完成任务。 |

### 发展趋势

当前钉钉的产品定位已经从移动办公扩展为“企业组织协同办公和应用开发平台”。开放平台首页强调以 PaaS 作为企业和生态的数字化底座，开放范围包括原子级 API、场域级能力和数据级能力。这意味着钉钉的发展重点从提供固定功能，转向提供可组合、可扩展的企业数字化能力。

## 钉钉解决什么问题

### 1. 降低组织沟通成本

企业中的信息往往分散在电话、短信、邮件、个人聊天工具和多个群组中。钉钉通过企业组织架构、通讯录和工作群，把人员关系与工作沟通结合起来，减少“找不到人、找不到信息、无法确认状态”的问题。

### 2. 统一办公入口

审批、考勤、会议、文档和任务如果分别使用不同系统，会产生重复登录、重复录入和数据割裂。钉钉工作台将这些能力集中到一个入口，并允许企业把自己的业务系统嵌入其中。

### 3. 让企业流程可追踪

传统口头或聊天式协作容易出现遗漏和责任不清。审批、任务、待办、事件订阅和消息记录可以把流程变成可追踪的数字记录。

### 4. 连接企业已有系统

企业通常已经拥有 ERP、CRM、OA、项目管理、代码仓库、客服和数据平台。开放平台通过 API、事件、连接器和机器人，把这些系统的状态同步到钉钉，减少人工搬运信息。

### 5. 用机器人减少重复劳动

机器人可以处理固定格式的通知、查询、提醒、分派和结果汇总，让人员把时间用于判断和决策，而不是重复转发消息或查找数据。

### 6. 为 AI 提供企业工作场景

通用聊天机器人只能回答问题。接入钉钉后，AI 机器人可以结合组织身份、企业知识和业务 API，在权限范围内完成查询、摘要、提醒和流程操作，成为工作入口的一部分。

## 技术路线

### 总体架构

钉钉的技术路线可以概括为：**多端客户端 + 云端 SaaS + 组织身份与权限 + 开放 PaaS + API/事件/消息连接 + AI 与自动化**。

```text
钉钉客户端
Android / iOS / Windows / macOS / Web
              |
       钉钉云端平台和组织服务
              |
   身份、通讯录、群聊、消息、办公应用
              |
   开放 PaaS：API、事件、应用、连接器
              |
企业后端 / 第三方系统 / 数据库 / AI 模型
```

### 开放平台的核心技术机制

| 机制 | 作用 |
| --- | --- |
| 应用注册 | 在开发者后台创建企业内部应用、机器人应用或其他应用，获得应用身份和配置入口。 |
| 身份认证 | 通过应用凭证、访问令牌和 OAuth 等机制确认调用者身份与授权范围。具体流程以对应 API 文档为准。 |
| REST/HTTP API | 以 HTTP 请求调用组织、用户、消息、审批、群聊和业务相关能力，通常使用 JSON 传输数据。 |
| 事件订阅 | 让钉钉把用户、群聊或业务事件通知给开发者服务，适合实现双向机器人和自动化流程。 |
| Webhook | 为简单的消息推送提供直接的 HTTP 入口，典型场景是自定义群机器人。 |
| Stream 模式 | 由机器人服务与钉钉建立长连接或流式事件通道，适合接收机器人消息和事件，减少公网回调地址配置。实际支持范围以当前文档为准。 |
| 消息与互动卡片 | 支持文本、Markdown、链接、ActionCard、Feed、互动卡片等形式，把通知升级为可操作界面。 |
| 连接器 | 把外部系统的事件、数据和动作映射到钉钉，减少重复开发。 |
| PaaS 开放 | 从单个 API 扩展到工作台、场景群、应用、数据和行业业务能力，支持企业和生态伙伴二次开发。 |

### 机器人技术路线

钉钉机器人可以按通信方向分为三类：

1. **单向推送型**：外部系统调用钉钉 Webhook，机器人向群里发通知，不负责理解用户消息。
2. **双向对话型**：钉钉把用户消息或事件发送给机器人服务，机器人处理后再回复消息或卡片。
3. **业务执行型**：机器人除了对话，还调用企业 API、钉钉 Open API 或工作流，实际完成查询、审批、创建任务等动作。

对应的技术链路是：

```text
消息/事件输入
  -> 身份和签名校验
  -> 幂等处理与权限判断
  -> 意图识别或命令路由
  -> 调用业务系统、数据库或 AI
  -> 生成消息/卡片
  -> 调用钉钉发送接口或 Webhook 回复
  -> 记录日志、耗时和错误
```

### 安全与可靠性要点

机器人开发时至少要考虑：

- AppKey、AppSecret、Webhook、签名密钥和 AI API Key 不能提交到 Git 或写入前端代码；
- 校验钉钉请求的签名、时间戳、来源和事件类型；
- 对事件 ID、消息 ID 或业务单号做幂等处理，避免重复执行审批、扣款或通知；
- 根据企业、部门、角色和用户身份限制机器人可访问的数据；
- 对外部输入做长度限制、内容校验和提示词注入防护；
- 对钉钉 API 调用实现超时、重试、限流和错误记录；
- 对消息发送失败、业务执行成功但回复失败等情况保留可追踪日志；
- 生产环境使用 HTTPS、密钥管理、最小权限和独立的运行账号。

## 钉钉机器人类型对比

钉钉开放平台的机器人文档目录包含群机器人、自定义机器人、企业内部机器人、第三方机器人和机器人应用等不同路径。实际开发前先选择正确的机器人类型。

| 类型 | 典型用途 | 交互方向 | 开发复杂度 | 适合场景 |
| --- | --- | --- | --- | --- |
| 自定义群机器人 | 告警、构建结果、定时通知 | 主要是服务端推送到群 | 低 | 先快速验证消息推送 |
| 企业内部机器人 | 企业员工问答和内部自动化 | 双向 | 中 | 企业内部业务机器人 |
| 机器人应用 | 独立的机器人应用、单聊和群聊能力 | 双向 | 中到高 | 正式产品化开发 |
| 第三方系统机器人 | GitHub、GitLab、Jira 等系统接入 | 由外部事件触发 | 低到中 | 研发和项目协作通知 |
| 场景群/群模板机器人 | 面向特定业务场景的群协作 | 双向或事件驱动 | 中到高 | 行业化、流程化协同 |
| AI 机器人 | 自然语言问答、知识库和任务执行 | 双向 | 中到高 | AI 助手和业务 Agent |

## 重点理解：自定义群机器人与机器人应用

### 自定义群机器人

自定义群机器人通常在钉钉群设置中创建，平台会提供一个 Webhook 地址。外部服务向该地址发送 JSON 请求，钉钉将内容显示到群里。

典型特点：

- 接入快，通常不需要完整开发一个钉钉应用；
- 适合文本、Markdown、链接、卡片等通知；
- 可以配置关键词、加签或 IP 等安全策略，具体以当前群机器人配置页为准；
- 主要用于“系统发生事件后通知群”；
- 通常不适合复杂的用户问答、用户身份识别和业务操作。

### 机器人应用

机器人应用是在开放平台中注册和配置的应用，通常需要处理应用身份、权限、事件接收和消息发送。

典型特点：

- 可以接收用户消息或机器人相关事件；
- 可以结合组织身份和开放 API 实现更细粒度的权限控制；
- 可以回复文本、Markdown、互动卡片等内容；
- 能够连接企业系统、知识库和 AI 模型；
- 适合做长期运行、可扩展、可审计的正式业务机器人。

## 后续开发建议

你后面要在钉钉中开发机器人功能，建议按下面的顺序推进：

### 第一阶段：先做单向通知

选择自定义群机器人，完成一个最小闭环：

```text
本地脚本或后端服务 -> 钉钉群 Webhook -> 群消息
```

可以先实现构建结果、服务异常或定时任务通知，验证消息格式、签名、网络访问和失败重试。

### 第二阶段：做双向机器人

如果需要“用户在钉钉中发送问题，机器人返回答案”，应转向企业内部机器人或机器人应用，并重点处理：

- 消息接收方式：Stream 或 HTTP 回调；
- 机器人身份和用户身份；
- 消息回复接口；
- 事件去重和超时；
- 组织权限与敏感数据访问。

### 第三阶段：接入业务系统或 AI

把机器人拆成几个清晰模块：

```text
钉钉适配层
  -> 消息解析和回复
业务路由层
  -> 命令、意图和权限
业务服务层
  -> ERP/CRM/数据库/工作流/API
AI 能力层
  -> LLM、知识库、RAG、工具调用
基础设施层
  -> 日志、缓存、队列、密钥和监控
```

不要让钉钉 Webhook 处理函数直接承载所有业务逻辑。这样可以避免将来更换消息通道、增加 AI、接入多个群或支持卡片交互时产生大范围改动。

### 推荐的最小项目结构

```text
dingtalk-bot/
├── src/
│   ├── dingtalk/       # Webhook、API、事件和消息适配
│   ├── handlers/       # 命令或事件处理器
│   ├── services/       # 业务系统和 AI 调用
│   ├── security/       # 签名、权限、密钥读取
│   └── main.*          # 服务启动入口
├── tests/
├── .env.example
└── README.md
```

## 结论

钉钉的核心价值是把企业组织、沟通、办公流程和业务应用放在同一个平台中，并通过开放 PaaS 让企业和开发者进行扩展。

钉钉机器人是这个平台上的自动化入口：简单场景可以通过群 Webhook 发送通知，复杂场景则可以注册机器人应用，接收用户消息和事件，调用企业系统或 AI，再通过消息和互动卡片完成反馈和操作。

如果目标是后续持续开发功能，建议从“自定义群机器人通知”开始验证，再逐步升级到“机器人应用 + 事件接收 + 业务 API + AI/知识库”。
