## 一、系统概述与设计目标

**设计**:钉钉群 → 钉钉机器人 → AstrBot(消息接入,内置 RAG 知识库召回 + agent 执行器生成)→ 原路回复。核心关切是**回答质量**。定位经过两次修正:"普通 FAQ 问答系统" → "FAQ 智能体问答系统" → 最终定准为**查询路由 + agentic RAG**——智能体性来自三点:检索是工具、澄清是多轮状态、"答还是问"是自主决策;而 FAQ 直答恰恰是确定性管道,不"智能体",这正是它的价值。

**原理对照**:这个分层本质是能力边界思维(生成机制·下·二)——**确定性管道(直答)解决"可靠",生成管道(RAG)解决"覆盖",互补而非互斥**。直答绕开生成环节,等于不在模型"能编"的位置上给它机会,质量可审核、可复现;这是幻觉机制(生成机制·上·二)给出的最硬质量手段。

**改进**:对外(简历/面试)的表述用"分层问答系统:确定性 FAQ 直答 + agentic RAG 兜底 + 澄清拒答路由",比"FAQ 智能体问答系统"准确,且每个词都经得起追问。

## 二、知识库构建:答案之书与主知识库

**设计**:双库结构。**答案之书**——独立知识库,带 verified 标记,条目格式:问题 / 标准答案 / 别名问法 / 验证日期 / 时效提示;从 Top 10~20 高频事实类问题人工写就。**主知识库**——保持现状承载文档类知识。书靠飞轮生长:RAG 日志 → 答得好且被反复问 → 人工审核 → 沉淀入书。

**原理对照**:
- 答案之书是 chunking 的特解(检索原理·四):FAQ 一问一答天然一块,语义聚焦不稀释;"别名问法"字段相当于**查询扩展**——正面缓解"问题-答案形态差"失效(用户问句和文档表述的几何距离被人为拉近)
- verified / 验证日期 / 时效提示就是"元数据是块的另一半"的直接实践:过滤、溯源、淘汰过期答案全靠它
- [待回填:答案之书 v0 条数与 Top 高频问题清单]

**改进**:别名问法覆盖口语化表述("登录不上去了"这类);每条沉淀入库时保持一问一答一块,不为凑块合并多条。

## 三、检索与召回

**设计**:AstrBot 内置向量召回;FAQ 命中走**语义匹配 + 置信阈值**(余弦相似度 0.75~0.8 起步),置信分三档:高 → 直答;中 → 答案+标来源;低 → 落入 RAG 生成。

**原理对照**:
- "0.75~0.8 **起步**"符合原理层的告诫(检索原理·一):阈值不是普适常数,量纲依 embedding 模型而定——六步清单第 5 步"定阈值"就是校准动作,起步值只是先验
- 置信三档是"漏检 vs 噪声"配比(检索原理·二)的分级处理:高置信吃精度、低置信吃召回,中档交给人(带来源),不在一个阈值上赌全部
- **已知未封的洞**:五类失效模式里,专名类(`ERR-1001` vs `ERR-1002`)和否定类("开通"vs"关闭")单靠向量必然翻车;设计里还没有显式的混合检索(BM25)或查询改写——钉钉场景"系统名+功能名"类查询不会少

**改进**:golden set 里单列专名类、否定类 case,回归时专门看这两类的命中;命中差则上关键词前置/混合检索。[待回填:首轮误路由统计中专名/否定类占比]

## 四、rerank 与上下文组装

**设计**:现状为 AstrBot 内置召回,管线未见独立精排段。[待回填:AstrBot 召回链路是否内置重排、top-k 取值]

**原理对照**:
- 两段式(检索原理·三)的适用判断:**A 路由(直答)不需要 rerank**——语义匹配 + 置信阈值已经完成"从几十条里挑一条";**B 路由(RAG 生成)才受益**——喂给生成的上下文质量决定答案质量
- 组装顺序接 lost in the middle(生成机制·下·一):检索片段按相关度排序,最相关的放上下文最前——这步不动库、不加模型,是最便宜的改进
- 双塔的糙是结构性的,但"先别急着上 reranker":**bad case 先翻 top-k 原文,定位是"没检到"还是"检到了没用好"**——前者改检索/切法,后者才是 rerank 的病

**改进**:按上一节的 golden set 回归结果决策;若 B 路由"检到但排序乱"类 case 多,再加独立 reranker(两段 K 独立调)。

## 五、查询理解与路由:四路由

**设计**(本系统最核心的设计,完整存档):

| 路由 | 判定条件 | 动作 |
|------|---------|------|
| A. FAQ 直答 | 答案之书语义匹配,高置信 | 直接返回标准答案,标注"已验证" |
| B. RAG 生成 | 知识库内,问题完整 | 按原因/结果/过程模板定向生成,带来源引用 |
| C. 澄清 | 问题欠完整/意图不明 | 一轮追问,≤3 个编号选项,按选择再走 A/B |
| D. 拒答 | 知识库外/超纲/敏感 | 明说不知道,给替代路径(转人工/查 XX) |

配套:**双轴原则**(路由轴=库内/库外 × 完整/欠完整,决定走哪条;形态轴=原因/结果/过程,决定答案形状,对 A/B 都适用);意图分类与定向生成**合并单次调用**,不做多级流水线。

**原理对照**(复盘的核心一节):
- 原始三分法("真理类/非真理类")为什么错,原理层给出了完整解释:**可验证性是治理属性,不是检索属性**——把它当路由轴,和"库内外"这根正交轴压在一起,必然互相穿透("报表接口为什么慢"既是库内事实又要求原因定向)
- 澄清**一轮封顶**是对话版的滚雪球对策(生成机制·上·二):多轮澄清让早期误解的自我强化叠加,且群聊场景用户容忍度极低
- 误路由是静默失败 → golden set 给每条标**预期路由**,回归时对照实际路由——这是"让静默失败可见"的工程化,也是质量层评测闭环的入口
- 合并单次调用:链路越长越难排查——错误排查面最小的架构选择
- 形态轴模板 = 用结构约束降低生成自由度,拿确定性换质量

**改进**:误路由案例按"A 误 B / B 误 D / C 过度触发…"分类归档,每类对应一个 prompt 或阈值修正,不混在一锅改。[待回填:首轮回归的"问题-预期路由-实际路由"对照表]

## 六、生成端

**设计**:AstrBot persona / system prompt 承载四路由规则与澄清行为;B 路由按形态轴模板定向生成;每条 RAG 答案**带来源引用**。

**原理对照**:
- 带来源引用一举三得:把事实放进上下文让续写有据(对抗幻觉)、给用户信任锚点、给飞轮提供审核依据——一个设计点吃三层红利
- 行为规则放 persona 而不微调:对应"知识 vs 行为"决策轴(生成机制·下·四)——路由规则是稳定行为,prompt 正是它的主场
- 采样参数:A 路径无生成(确定性管道的又一红利);B 路径是事实问答,应低温 + 模板约束。[待回填:AstrBot 当前温度与默认参数]

**改进**:B 路由上下文组装按相关度排序(接第四节);拒答话术显式给替代路径(接待定决策点:转给谁、怎么留痕)。

## 七、治理与飞轮

**设计**:每周五 30 min 节奏——审核本周 RAG 日志,好答案沉淀入书(带验证日期/负责人/时效提示);本周新误路由案例补进 golden set。

**原理对照**:
- "书是长出来的"对抗两类过期:embedding 的知识截止(检索原理·一)和答案本身的时效;人工审核关用"是否可验证"做门槛——这正是该轴从路由挪到治理后的正确岗位
- golden set 随坏案例生长 = 评测闭环的复利:每个生产事故都变成回归资产,"只认数字不认感觉"

**改进**:飞轮先转起来再谈优化——30 分钟的周节奏,立住比精美重要。[待回填:首个周期执行情况与沉淀条数]

## 九、FAQ

**Q:FAQ 直答不走生成模型,不怕答非所问吗?**
匹配错的风险由置信阈值管(低置信落 RAG,不硬直答);换生成模型答反而引入幻觉面。确定性管道的价值就是可审核、可复现——用机制换机制,不用机制赌机制。

**Q:这个系统的"智能体"含量到底在哪?面试怎么讲?**
在路由层不在生成层:检索是工具、澄清是多轮状态、"答还是问"是自主决策。一句话区分:"不是给 LLM 套了个 FAQ 壳,而是让 LLM 当调度员,确定性的事走管道,不确定的事先问清,超纲的事坦白说。"这句话同时展示了 agentic RAG 的理解和工程分层的判断。
