# LLM 基础认知 · 提示词工程(延伸篇)

> 层:原理层(延伸篇第二篇)| 主题:提示词工程解决什么问题 / 套路↔原理对照 / 边界与升级路径 / 本人实践对照
> 版本:学习版——每个套路必须挂得回一条生成机制原理;与姊妹篇分工:[上下文工程](LLM基础认知-上下文工程.md)管整个窗口(六族全景),本篇展开其中第五族(结构化与位置):进入窗口的指令与示例怎么写

一句话版:**提示词工程是上下文工程的写入侧子集:管"指令与示例怎么写"。每个常用套路背后都有一条生成机制原理(few-shot=ICL、CoT=生成即上下文、角色=分布引导、位置=注意力先验),而它的边界同样来自原理——表述性弱项写得救,机制性弱项写得再好也救不了,必须上工具。**

使用说明:本文是原理层延伸篇第二篇(评估过程见台账 Q8 第 24~26 次)。定位红线:不写技巧大全——套路的价值不在"咒语",在"为什么灵"与"什么时候不灵"。面试自检标准:套路↔原理对照表每行能脱稿讲;能救/不能救分界能脱口而出。

## 一、它解决什么问题

**是什么**:上下文工程的物理清单([上下文工程·一](LLM基础认知-上下文工程.md))里,指令与示例是唯一完全由你手写的部分——system 消息、格式要求、few-shot 示例、任务描述。提示词工程(prompt engineering)就是把这部分手写内容的利用率最大化:同样的模型、同样的预算,**写法决定输出分布落在哪**。

**解决的是行为可控性**:输出格式稳不稳、口径对不对、任务范围清不清、步骤乱不乱。但可控有一条原理级的分界线(见第三节):表述层面的失控,写法能收住;机制层面的失控,写法救不了。

**例子(可直接讲,约 1 分钟)**
FAQ 问答系统最早的 bad case 之一:超纲问题(知识库里没有的)模型必瞎编——这是机制(幻觉是固有属性,生成机制·上)。prompt 层的解法是在模板里写死任务边界:"仅依据提供的资料回答,资料没有就明确说不知道,并提示转人工"。一段话,源头封住(故事库 B 组"拒答封源头"卡)。落点:**表述层的失控,prompt 是对症药;这也是它唯一对症的病**。

## 二、套路↔原理对照表(核心)

每个套路挂一条原理——面试讲套路的段位差距,就在能不能说出右列:

| 套路 | 原理依据 | 一句话 |
|------|---------|--------|
| few-shot 示例 | ICL(in-context learning):示例改变条件分布 | 几个例子放进上下文就能改变行为,不动参数 |
| CoT(一步步想) | 生成即上下文:中间结论落成文字,成为后续生成的条件 | 草稿外化,每步踩在已写下的结论上 |
| 角色设定("你是资深法务") | 分布引导:把模型调到训练语料中对应人格/语域的分布 | 续写机的语境开关 |
| 格式约束 / 结构化输出 | 输出格式是分布的强约束;结构化输出把约束下沉到解码层 | 从"求它像 JSON"到"机制上只能出 JSON"(生成机制·下·二) |
| 位置策略(关键信息放开头、头尾重复) | lost in the middle:注意力偏头尾(生成机制·下·一) | 重要的话说两遍,放开头和结尾 |
| 任务分解(拆步、先理解再做) | 每步条件更明确,滚雪球概率低(幻觉滚雪球,生成机制·上) | 小步生成,错误早拦 |
| 采样参数配合 | prompt 决定分布形状,temperature/top-p 决定怎么抽(生成机制·上·三) | 写完 prompt 之后还剩的旋钮 |

三个值得多讲两句的行:

**1. few-shot=ICL(本行把补充资料的 ICL 占位展开)**。示例不是在"教知识",是把条件分布调到任务上:模型见过"这种输入→这种输出"的成对模式,后续就照着模式续。与微调的分界:示例走上下文(每次调用都要带、随时可换、占 token 预算),微调改参数(一次训练长期生效、更新要重训、不占预算)——正好对应生成机制·下·四的"知识 vs 能力"轴:教格式与边界用示例,改说话基线才微调。示例选择的工程学:**教边界案例,不教模型已经会的**;示例会被当格式模板逐字模仿——坏示例一样被学。

**2. CoT=生成即上下文**。普通模型用一句"先一步步分析"手动触发;推理模型把这件事内化成 thinking 并用强化学习训练强化(生成机制·下·三)。提醒两条:CoT 的价值在多步任务,简单任务上白花 token(接分级路由);thinking 文本不一定忠实于模型真实决策过程(补充资料占位),当参考可以,当解释承诺不行。

**3. 采样是 prompt 的另一半**。prompt 定分布,参数定抽取:FAQ 直答低温度求稳,创意发散高温度——两个旋钮配合,而不是只调一边。

## 三、边界与升级路径

**能救 / 不能救分界**(原理依据:能力边界四弱项,生成机制·下·二):

| | 内容 | prompt 的角色 |
|---|------|--------------|
| **写得救(表述性弱项)** | 格式遵循、口径与风格、任务范围澄清、示例教学、输出结构 | 对症:写清约束、给对示例就收得住 |
| **写不救(机制性弱项)** | 精确计算、训练截止后/私有事实、长文一致性、长流程不漂 | 不对症:必上工具——代码执行、检索(RAG)、外部状态+检查点 |

最危险的错觉:"prompt 再改改总能救"——它救表述,救不了机制;模型校准差+输出流畅,追问"你确定吗"往往只收获更流畅的重复。

**升级路径:prompt → RAG → 微调**(生成机制·下·四的默认顺序,这里从 prompt 的视角看):

- prompt 解决表述;表述解决不了**知识**(常变、要溯源、有权限)就上 RAG——把知识写进 prompt 是"静态知识灌注"的 prompt 版:更新要改模板、占预算、无溯源
- 知识也不是全部:**行为基线**(稳定口径、领域语言习惯)才轮到微调
- 面试标准题的拆法(生成机制·下·四"公司术语+口径"):口径=行为、事实=知识、表述=prompt——三件工具各管一段,不是站队题

## 四、实践对照:本人实践里的提示词工程

| 本人实践 | 对应套路/原理 | 出处 |
|---------|--------------|------|
| FAQ 拒答话术("资料没有就说不知道") | 任务范围澄清;幻觉机制性→源头封 | 复盘·查询路由;故事库 B |
| 定向输出(JSON 结构+校验重试) | 格式约束→结构化输出 | 复盘·生成端 |
| persona(客服口径) | 分布引导 | 复盘六 |
| 澄清追问一轮封顶 | 任务分解+预算控制 | 复盘·生成端 |
| 试点手册:分阶段提示词,每阶段带验收 | 任务分解;验收前置 | 工作流篇·案例 3 |
| 能力文档"先理解再写作"(提取事实→人确认→生成) | 任务分解,错误早拦 | 工作流篇·案例 2 |
| 演进系列模板+AGENTS.md 流程内嵌 | 长指令结构化(流程写进提示) | 工作流篇·案例 1 |

共同点:**没有一处是"咒语",全是结构化写作+原理对应**——这也是"提示词工程没被上下文工程取代,而是被收编"的实例:每一行都在管理进入窗口的信息,只是管的是手写的那部分。

**面试话术(1 分钟,可直接讲)**
我对提示词工程的定位:它是上下文工程的写入侧子集,管指令与示例怎么写。每个套路我都对应得出原理:few-shot 是 ICL,示例改变条件分布;CoT 是生成即上下文,草稿外化;角色设定是分布引导;位置策略对应 lost in the middle。更重要的是知道边界:表述性弱项写得救,机制性弱项——精确、事实、一致性、长流程——必须上工具,所以我系统里模型从不亲自算数、事实全走检索。判断一个 prompt 好不好,我看三点:可迁移(换模型基本还灵)、可解释(每个要素说得出来历)、可维护(结构化,像改代码一样改)。

## 五、误区与自检

**误区**

- "提示词=咒语,堆术语触发词"——起作用的是分布引导与约束明确,不是魔法词;一段朴素但结构清晰的指令,胜过一堆加粗的"非常重要"
- "示例越多越好"——示例占 token 预算、稀释注意力(上下文工程三约束);教会为止
- "CoT 触发词万能"——多步任务才值,简单任务白花钱(接分级路由)
- "再改改总能救"——分界线在表述 vs 机制,机制性弱项的直接答案叫工具

**自检三问**(答不顺的就是没消化)

1. few-shot 为什么有效?和微调什么区别?(ICL:改上下文 vs 改参数;知识可变走示例,行为基线走微调)
2. 什么时候 prompt 救不了?(四类机制性弱项→各自的工具)
3. 你的系统里提示词工程做了什么?(模板/persona/定向输出/拒答/分阶段+验收,各带一条原理)

## FAQ

**Q:提示词工程是不是过时了,被上下文工程取代了?**
没被取代,被收编:它是六族之一,且是日常动作密度最高的一族——每次调用都要写指令,不是每次都要动检索和记忆。面试被问关系,就答"子集+被收编",再反手讲一条套路↔原理对应,比背十个技巧加分。

**Q:好 prompt 的标准是什么?**
本专题自建三判据:可迁移(换个模型基本还灵,说明用的是通用原理不是某家的怪癖)、可解释(每个要素能说出对应哪条原理)、可维护(结构化分节,像改代码一样改,而不是一坨散文)。

**Q:few-shot 示例放几个、放什么?**
放边界案例和格式示范,不放模型已经会的常识;数量"教会为止",因为示例占预算、稀释注意力,坏示例还会被逐字模仿。示例本质是给条件分布找锚点,不是越多越好。
