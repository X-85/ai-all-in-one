# FastAPI 学习指南

一句话版：**FastAPI 是 Python 的异步 Web 框架，凭"函数签名即 API 契约"把类型标注变成生产力——校验自动、文档自动、异步原生，成了 AI 应用把 LLM 能力对外提供服务的默认出口。本篇回答四个问题：它用来干嘛、解决什么问题、学习要过哪些关卡、有哪些坑。**

使用说明：这是工程层的**技术栈学习指南**（知识型），与本层其他文档（复盘/横评，经验型）体裁不同。它为什么诞生、与 Django/Flask 的因果链，见 [Django-Flask-FastAPI演进路线](../knowledge/doc/lang-evolution-notes/Django-Flask-FastAPI演进路线.md)；选型时"该不该选它"，见 [语言主战场速查](../knowledge/doc/lang-evolution-notes/语言主战场速查.md)——本篇只管"怎么学、怎么用对"。

## 一、它是什么，用来干嘛

FastAPI 是 **Web 框架**（不是语言——你写的是纯 Python，判定见演进篇 FAQ Q6）：负责收 HTTP 请求、路由分发、参数校验、返回响应。放在 AI 应用的技术栈里看，它的位置是**能力出口层**：

```text
用户/前端/钉钉机器人 → HTTP API(FastAPI) → 你的 Python 逻辑 → LLM / 向量库 / 知识库
```

LLM 的能力再强，也要有一个东西把它变成"别人能调的服务"——接口、校验、文档、并发，就是 FastAPI 干的活。Python 的 AI 生态（一切 LLM/向量库 SDK 都先是 Python 的）+ 它的两个招牌特性（下一节），让"LLM 应用 API 层"这个位置几乎被它默认占住——教程、模板、LangServe 这类上层封装，清一色以它为底座。

## 二、解决什么问题（四个当下工程收益）

**1. 校验与文档的双重手写浪费 → 签名即契约。**
传统写 API：参数校验手写一堆 `if not x`，接口文档手写一份 Markdown，两边必然漂移。FastAPI 里函数签名就是契约——参数写类型标注，错的请求进函数之前就被拦下（返回 422），`/docs` 交互式文档从签名自动生成。**工程推论：契约只写一遍（签名），校验和文档都是派生物**——"文档过期"这类事故在这里结构性消失。

**2. 数据建模散乱 → Pydantic 模型。**
请求体、响应体都是 Pydantic 类定义：嵌套结构、默认值、约束（`Query(10, ge=1, le=100)`）全在类型系统里。**工程推论：同一个思路延伸到 LLM 侧**——让模型输出 JSON 时，输出 schema 也用 Pydantic 定义，"模式定义一次、校验与解析全派生"的闭环就通了（呼应 [提示词工程](LLM基础认知-提示词工程.md) 的"格式=输出约束"）。

**3. 等 LLM/查库/外呼时吞吐塌方 → 异步原生。**
LLM 生成一次要几秒到几十秒，是典型 IO 密集。同步栈一个 worker 同一时刻只伺候一个请求，全在干等；`async def` 路由直接消费 asyncio，一个进程同时挂着成百上千个等待中的连接。**工程推论：AI 服务的吞吐瓶颈几乎总在"等"，异步不是可选项**；流式响应（打字机效果，SSE）是 LLM 接口的标配形态。

**4. 工程杂事重复 → 依赖注入。**
鉴权、数据库 session、分页参数，用 `Depends()` 统一声明、按需注入路由，不再全局变量满天飞。**工程推论：可测试性**——测试时把依赖换成假的（mock DB、假用户），单测不用起真环境。

## 三、学习路线：五道关卡（每关带验收标准）

- **第 0 关（前置）**：Python 基础、类型标注（`list[str] | None` 这类现代写法）、venv/uv 环境（见 [构建工具链速查](../knowledge/doc/lang-evolution-notes/构建工具链速查.md)）。验收：能读懂带完整类型标注的函数签名。
- **第 1 关（最小可用）**：路由与路径/查询参数、Pydantic 请求/响应模型、`/docs`。验收：起一个服务，POST 一个 JSON，类型错的字段收到 422，并在 `/docs` 看到自己的全部接口。
- **第 2 关（工程化）**：依赖注入（鉴权/DB session）、异常处理、配置管理（pydantic-settings + .env）、CORS、lifespan（启动时加载模型）。验收：数据库连接和鉴权全做成 `Depends`，路由代码里零全局变量。
- **第 3 关（异步与流式，AI 味最浓，本指南的重心）**：async/await 的正确用法、`StreamingResponse`/SSE 流式输出 LLM token、BackgroundTasks、长任务设计。验收：写一个流式 `/chat` 接口，客户端能逐 token 收到生成内容。
- **第 4 关（上线）**：uvicorn/gunicorn worker、Docker 打包、健康检查端点、`TestClient` 接口测试。验收：容器里跑起来，`curl /health` 返回 200，pytest 过一个接口测试。

时间感：第 1~2 关各半天；**第 3 关是 AI 应用岗的核心差异点**，值得多花一倍时间；第 4 关按需。

## 四、提醒：常见的坑

1. **async 不是装饰器，是调度方式**。在等别人（LLM/库/外呼）→ async；自己在算 → 别 async（混进事件循环会把所有请求卡死）。FastAPI 对同步 `def` 路由会自动丢线程池，所以"全写 def 也能跑"——但那样就白选它了。判断口诀见演进篇 FAQ。
2. **Pydantic v1/v2 有断层**：`.dict()` → `.model_dump()`、校验器写法全变。网上教程新旧混杂，报错第一反应查版本。
3. **`/docs` 是契约，别再手写一份接口文档**——两份契约必漂移，自动文档的意义就是消灭第二份。
4. **版本至今 0.x，不是质量信号**。作者对 API 稳定承诺保守，生产环境大量在用，别等 1.0。
5. **LLM 场景专项**：用 SDK 的 async 版本才是吞吐正解；超时与重试必须在 API 层设置，别让 worker 无限挂等；流式接口记得处理客户端断连。
6. **别拿它当重 CPU 计算的宿主**：计算扔进程池，或干脆独立服务——FastAPI 的优势在 IO 编排，不在算力。

## FAQ

约定：随真实疑问追加，每条几句话内。

**Q1：要先学 Django 或 Flask 吗？**
不用，FastAPI 自足。概念上知道"全家桶 vs 微内核"的谱系位置即可（演进篇 5 分钟），那是选型视角，不是学习前置。

**Q2：FastAPI 能做前端页面吗？**
能塞 Jinja2 模板，但不是主业。前后分离时代它的定位就是 API 层；要界面，配一个前端或用 Gradio/Streamlit 做演示壳。

**Q3：和 Flask 到底怎么选？**
内部小工具、原型 → Flask 够；对外 API、AI 服务、要文档 → FastAPI。一张表见 [语言主战场速查](../knowledge/doc/lang-evolution-notes/语言主战场速查.md)。

**Q4：为什么教程都在用 uvicorn？**
分工：FastAPI 是框架（管逻辑），uvicorn 是 ASGI 服务器（管网络）——框架是电器，uvicorn 是插座（演进篇第五节"WSGI/ASGI"）。

**Q5：学习资源从哪开始？（提问背景：10 年 Java 开发经验）**
主资源就是[官方文档](https://fastapi.tiangolo.com/zh/)（有官方中文版）——"教程-用户指南"按序过完即覆盖第 1~2 关，"并发与 async/await"章节对应第 3 关，不需要书和视频。Java 老手迁移极快，概念几乎全有对应：`@GetMapping` → `@app.get`、`@Autowired` → `Depends()`、DTO+`@Valid` → Pydantic 模型、内嵌 Tomcat → uvicorn、JUnit → pytest。唯一要重建的心智模型是**线程池（Thread-per-Request，阻塞无妨）→ 事件循环（单线程，阻塞是毒）**——即第四节坑 1；其余都是换拼写，不是换世界。
