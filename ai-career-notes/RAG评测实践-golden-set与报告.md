## 二、golden set 构成(建尺子)

目标 50~100 条**真实问题**(从群聊日志抽,不自己编),每条字段:**问题原文 / 预期路由(A/B/C/D)/ 标准答案要点(B 路由用)/ 来源(哪天的真实提问)**。

分层配额(总和即 golden set 规模):

| 分层 | 目标条数 | 说明 |
|------|---------|------|
| A 预期:FAQ 直答 | [待回填] | 答案之书覆盖的高频事实题 |
| B 预期:RAG 生成 | [待回填] | 库内完整问题,含原因/结果/过程三种形态各若干 |
| C 预期:澄清 | [待回填] | 欠完整问法(缺对象/缺系统名) |
| D 预期:拒答 | [待回填] | 库外/超纲/敏感,各占若干 |
| 专项:专名类 | [待回填] | `ERR-1001` vs `ERR-1002` 类,单列(复盘·三:向量必翻车的已知洞) |

原则:**预期路由是人工判定的 ground truth**;生产新误路由案例每周补入(golden set 是活资产,不是一次性考卷)。

## 三、指标定义(四问)

**第一问:路由对不对**(质量层的核心指标,误路由是静默失败,必须显式对照)

- **路由准确率** = 实际路由 = 预期路由的条数 / 总条数,并按 A/B/C/D 分列
- **误路由方向分布**:A→B / B→D / C 过度触发 / **该 D 没 D(漏拒,直接幻觉面)**……各自计数——方向不同,修的地方不同(阈值 / persona / 检索)
- **拒答正确率**(D 的查准):走了 D 的里面,确实该拒的比例

**第二问:答案全不全**(B 路由)

- **答案要点覆盖率** = 标准答案要点被命中的比例;评定方式:人工评 or LLM-as-judge(若用 judge,先抽样 20 条人工复核 judge 的一致率,再放手规模化——知道尺子的尺子准不准)

**第三问:快不快**

- 分路由延迟:P50 / P95(端到端,钉钉消息进→回答出)

**第四问:贵不贵**

- 每次问答平均 token 消耗与费用;输入/输出/缓存命中三档分列(计费口径见生成机制·上·一);A 路由(无生成)与 B 路由分开算——**分层的成本红利要能从账单上指出来**

## 六、决策触发线(数据说什么才动)

把复盘里的待定决策写成条件语句,防止"看哪个都想优化":

- 专名/否定专项命中 < [待回填:阈值] → 上关键词前置/混合检索(BM25)
- B 路由"检到但排序乱"类 case 占比 > [待回填:阈值] → 加独立 reranker(两段 K 独立调)
- C 过度触发 > [待回填:阈值] → 收紧澄清判定的 persona 规则
- 置信阈值 0.75~0.8 → 按首轮 A/C 误分布校准(阈值是校准出来的,不是抄来的)
- embedding/生成模型选型 → **基线(首轮报告)建立后再动**,换模型后重跑全量对比
