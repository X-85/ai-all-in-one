# 面试故事库

> 层:证据层 | 系列位置:证据层第一篇 | 用法:每张卡 = 一个可讲 2 分钟的真实故事(情境→动作→结果→学到) | 素材全部出自台账与文档,可溯源

一句话版:**面试官不信"我熟练使用",只信真实故事——每张卡都来自踩坑记录,按题型分类,练到能脱稿讲 2 分钟。**

使用说明:四段式讲故事,先讲"情境"钩住人,最后落"学到";`适用` 标签按面试题型对号入座;`[待回填]` 卡骨架已好等素材;出处均指向台账 Q 编号,细节可回查。

## A. 排障类(证明"我真的跑过生产级东西")

### A1. 静默失败:C# 篇页面神秘缺失
- 情境:演进站点一次新增 13 篇文档,构建成功、零报错,唯独 C# 篇页面 404
- 动作:排除法定位到文件名——`C#演进路线.md` 里的 `#` 被 Astro 的 glob loader 当成 URL 锚点,路径解析为空、内容静默丢失;改名 `CSharp演进路线.md`(侧栏与链接显示名仍是 C#),并把这条例外写进工作区约定
- 结果:页面恢复;此后全系列再没踩过同类坑
- 学到:**"没报错" ≠ "没问题"——产出后要主动验收(构建页数、死链检查);踩坑要沉淀成约定,同一个坑不咬第二次**
- 适用:"讲一个你排查过的诡异 bug" / "agent 的静默失败怎么防"
- 出处:Q4 第 9 次

### A2. 大小写 404:本地正常,线上残缺
- 情境:站点本地全部正常,推上 GitHub Pages 后部分章节 404
- 动作:对照 404 清单发现规律——全是含大写字母的文件名;Astro 默认把 slug 转小写,而 Pages 区分大小写。自定义 generateId 保留原始大小写;顺带扫出 `.md` 互链是死链,加 rehype 插件重写为站内路由
- 结果:全站恢复,死链检查为空
- 学到:**本地与部署环境的差异是隐形 bug 源;修一个问题时顺带扫一遍同类问题**
- 适用:环境差异类 bug / "上线前你怎么验收"
- 出处:Q2 第 2 次

### A3. CI 409:两个 workflow 抢一个产物
- 情境:Pages 部署偶发 409,两个站点互相覆盖
- 动作:两处并发竞争——withastro/action 内置上传,显式再传同名产物必 409;仓库还有一个旧的 push 触发 workflow 与新站抢同一个 Pages 地址
- 结果:删冗余上传步骤、旧站改手动触发;后来给求职专题建站时直接"双站一次构建、合并上传",从架构上消灭竞争
- 学到:**共享资源(一个仓库只有一个 Pages 地址)的并发冲突,要么互斥、要么合并,不能装看不见**
- 适用:CI/CD 排障 / 资源竞争类设计题
- 出处:Q2 第 2-3 次、Q9

## B. RAG 设计演进类(证明"系统是我设计的,不是抄的")

### B1. 从三分法到四路由:一次被推翻重来的设计
- 情境:FAQ 问答系统初版按"真理类 / 非真理类 / 意图不明"三分处理所有提问
- 动作:复盘时接受了关键商榷——"是否可验证"和"库里有没有"是两根**正交的轴**,压成一根必然互相穿透("报表接口为什么慢"既算事实类又要求原因输出);拆成路由轴(库内/库外 × 完整/欠完整)+ 形态轴(原因/结果/过程),并补上初版漏掉的第四条:**超纲拒答**
- 结果:四路由蓝图(FAQ 直答 / RAG 生成 / 澄清 / 拒答),系统定位收敛为"查询路由 + agentic RAG"
- 学到:**分类设计的铁律是轴要正交;被指出错误时,先检验轴,再修补类目;"我不知道"是质量功能,不是失败**
- 适用:"讲一个你的设计被挑战后变好的经历" / RAG 架构设计题
- 出处:Q7 第 1 次

### B2. 拒答路由:把幻觉主产区封在源头
- 情境:知识库外的用户提问,初版会被硬塞进 RAG 生成——模型在低相关片段上强行编答案
- 动作:加第四条路由,库外/超纲明确拒答并给替代路径(转人工 / 查 XX);FAQ 命中加置信三档:高置信直答、中置信带来源、低置信落 RAG
- 结果:幻觉最高发的路径从源头封住 [待回填:首轮回归的误路由与拒答正确率数据]
- 学到:**对抗幻觉最硬的手段不是更聪明的 prompt,是不给模型编的机会;置信分层 = 不在一个阈值上赌全部**
- 适用:幻觉治理 / "RAG 答不准怎么办"
- 出处:Q7、复盘第五节

### B3. 澄清一轮封顶:短链路哲学
- 情境:意图不明的提问,理论上多轮澄清"更准"
- 动作:定死澄清**一轮封顶 + ≤3 个编号选项**;意图识别与定向生成合并为单次 LLM 调用,不做多级流水线
- 结果:链路短、误路由排查面小、群聊场景体验可控
- 学到:**多轮澄清是对话版的滚雪球——早期误解自我强化;链路每加一环,排查难度翻一倍**
- 适用:交互设计 / agent 自主性边界
- 出处:Q7

### B4. 答案之书:书是长出来的
- 情境:高频 FAQ 需要确定性质量的答案,不能靠每次生成赌运气
- 动作:人工写 v0(问题/标准答案/别名问法/验证日期/时效提示),带 verified 标记独立成库;飞轮让书自己长——RAG 日志里"答得好且被反复问"的进人工审核队列,通过后沉淀入书
- 结果:高频问题直答绕开生成,质量可审核、可复现 [待回填:v0 条数与首月沉淀速度]
- 学到:**能不经过生成的答案就是最确定的答案;知识库不是一次写成的,是运营出来的**
- 适用:知识库治理 / FAQ 系统设计
- 出处:Q7

## C. 人机协作类(证明"我指挥 agent,不是被 agent 指挥")

### C1. 并行会话撞文件:多 agent 的"先读后写"
- 情境:两个 AI 会话并行给演进系列接线,同时改 chapters.ts,写入互相覆盖;台账编号也被两轮各记了一次"第 6 次"
- 动作:确立流程——动笔前重读台账与文件现状、改动纯增量、失败后重读再重试;编号冲突核对后修正并注明
- 结果:之后多篇并行产出零冲突
- 学到:**多 agent 并行的冲突管理和多人协作一个道理:先读后写、增量提交、留痕对账**
- 适用:"agent 协作出过什么问题" / 多会话管理
- 出处:Q4 第 10-11 次

### C2. 20 篇长文量产:把判断固化成模板
- 情境:要产出 20 篇结构严格一致的因果链长文,跨几十个会话、多个并行进程
- 动作:三件套——模板(不变件 + 按类型可变件)、AGENTS.md 流程(必读文件 → 六步产出 → 注意事项)、台账(进度/踩坑/决定);每篇产出带验收
- 结果:任何新会话零口令接续("写 X 演进路线"一句话开工),20 篇全同构,踩坑零二犯
- 学到:**人的判断固化成结构,agent 负责填空;上下文喂对,产出就稳——这是用 AI 量产知识的内核**
- 适用:"你怎么用 AI 提效" / 知识管理
- 出处:Q1/Q4 全程

## 使用建议

- 每张卡练到 **2 分钟脱稿**;先讲情境(钩子),中段动作(细节),最后落学到(升华)
- 面试前按"适用"标签过一遍,按题型备卡,一卡可多用;同时过一遍 [补充资料](LLM基础认知-补充资料.md) 的"术语对齐"表,确保黑话听得懂、对得上
- **卡库随台账生长**:每解决一个新问题,回头补一张卡——这是它和背题库的本质区别

## FAQ

**Q:这些故事会不会太小、不够"大厂"?**
小而真 > 大而空。面试官用故事验真——`#` 被当锚点这种细节,没踩过的人编不出来;而"学到"一段展示的是从坑里提炼规律的能力,这才是他们要看的。

**Q:同一张卡被追问细节怎么办?**
出处都指向台账 Q 编号,细节可回查(events.md 里连当时怎么发现的都记了);练卡时把出处原文也过一遍,追问就是送分题。
